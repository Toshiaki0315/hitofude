# 実装タスク一覧

仕様書 [spec.md](spec.md) §9 のロードマップを、**TDD で回せる粒度**まで分解したもの。
着手時に `[ ]` → `[~]`（作業中）→ `[x]`（完了）に更新する。

**進め方のルール**
- 1 タスク = 1 コミット（テスト + 実装）を基本とする
- 各タスクは「テスト」欄に書かれたテストを**先に**書いてから実装する
- フェーズの「完了条件」を満たすまで次のフェーズに進まない

凡例: `[ ]` 未着手 / `[~]` 作業中 / `[x]` 完了

1. **`.app` にネイティブ拡張を足さない。** py2app は F-6 で 2 回踏んでいる
   （PIL の本体が入らない・署名済み `.dylib` を壊す）。残り 1 個のタスクが
   署名と公証なのに、そこへ GPU 付きの拡張を持ち込まない
2. **別プロセスなので巻き込まれない。** in-process のモデルが abort すると
   Qt ごと落ちる（exit 139 を追いかけた実績がある）。HTTP なら最悪でも無応答
3. **R3 を守れる。** 相手が HTTP だけなら `core/` は何にも触れず、テストは
   応答を差し替えるだけで書ける（CI にモデルを置かなくてよい）

代わりに**利用者が Ollama を別途入れる**必要がある。無ければ機能ごと畳む
（メニューを灰色にして入れ方を案内する）。

|     | タスク | 内容                                                             | 規模   |
| --- | ------ | ---------------------------------------------------------------- | ------ |
| [x] | L-1    | **開いているノートの要約・レビュー**（vault 全体は見ない）      | 中     |
| [x] | L-2    | **vault 全体への質問**（FTS5 で拾い、**出典付き**で答える）     | 中     |
| [x] | L-3    | **関連ノートの提示**（「これに関係するノート」）                | 小〜中 |
| [ ] | L-4    | 埋め込み検索（L-2 の取りこぼしが**実測で**問題になったときだけ）| 中     |

**L-2 で分かったこと（2026-08-22）**: 質問をそのまま探すと**当たらない**
（全文検索は打った通りの並びを探すので、「予算について何が決まった？」は
出典 0 件だった）。`core/keywords.py` で語に切って 1 語ずつ探す形にした。
**形態素解析は入れない**（辞書ごと `.app` に乗る）。漢字・カタカナの
連なりを拾い、送り仮名 1 文字は挟んで繋ぎ（「買い物」）、助詞では切る
（「会議の議事録」）。**ひらがなだけの語は拾えない**のが割り切り。
ここで取りこぼしが実際に困るようなら L-4（埋め込み）へ進む。

**L-1 から始める。** 検索の当たり外れが混ざらないので、モデルの実力と
速さを素で測れる。

**L-3 は LLM を通さない**（2026-08-22 の実装で決めた）。関係の根拠は既に
索引の中にある（同じタグ・`[[…]]` の指し合い・題名の言及）ので、モデルに
選ばせると **なぜ関係するのか確かめられず**、待たされ、Ollama を入れて
いない人には何も出ない。索引から引けば即座に出て、理由も一緒に出せる。

**外せない約束**: 本文を勝手に書き換えない（R1。答えは別の場所に出し、
入れるのは押されたときだけ）／送り先は `127.0.0.1` に固定する（テストで
固定）／生成は打鍵の経路に入れない（§6.6）／**どのノートを見て答えたかを
必ず示す**（根拠を確かめられない要約は使えない）。

### 直したもの

**文字数の集計で画面が止まる** — 2026-08-17 に背景へ回した。

長い本文では集計に時間がかかり（実測 5 万文字で 69ms、負荷が高いときは
285ms）、打つ手を止めた 0.4 秒後にその時間だけ画面が固まっていた。
性能テストが高負荷時に落ちたのはこれを測っていたため。

| 本文       | 画面が止まる時間（前） | （後）                   |
| ---------- | ---------------------- | ------------------------ |
| 1,000 文字 | 1.4ms                  | 1.41ms（その場で数える） |
| 1 万文字   | 13.7ms                 | 0.09ms                   |
| 5 万文字   | 68.8ms                 | 0.33ms                   |
| 10 万文字  | 138.0ms                | 0.65ms                   |

**短い本文はその場で数える。** 1 フレーム（16ms）に収まるうちは、投げて
返す往復のほうが長くつく（境は 10,000 文字）。

**テスト終了時の segfault（exit 139）** — 2026-08-16 に原因を特定して修正。
macOS のクラッシュレポート（`~/Library/Logs/DiagnosticReports/Retired/Python-*.ips`）
21 件を読み直したところ、3 つの別々の原因が混ざっていた。

| 時期      | 落ちた場所                                                          | 件数 | 状態                                                                                     |
| --------- | ------------------------------------------------------------------- | ---- | ---------------------------------------------------------------------------------------- |
| 8/15      | `FSEventStreamCallback` → `PyGILState_Ensure`                      | 2    | 監視を終了前に必ず止めるようにした（`storage/watcher.stop_all`）                         |
| 8/14      | `QMimeDataWrapper::~QMimeDataWrapper`（`exit()` の中）              | 2    | **クリップボードが原因。** テスト終了前に空にする（`tests/conftest._release_clipboard`） |
| 8/9〜8/10 | `QWidget::~QWidget` / `QBuffer::writeData` / `QTextLine::cursorToX` | 16   | 当時のコードのもの。以後 6 日間再発なし                                                  |

**再現条件**: `QT_QPA_PLATFORM=offscreen` で、Python 側が作った `QMimeData` を
クリップボードに載せたまま終了すると **20 回中 20 回**落ちる。実機（cocoa）では
5 回中 0 回で、**アプリ側の問題ではない**。全件流したときに出たり出なかったり
したのは、後から走るテストが別の中身で上書きすると落ちなくなるため。
`tests/editor/test_exporter.py` を単独で流すと必ず再現した（修正前）。

回帰テストは `tests/test_teardown.py`（中で pytest を動かして終了コードを見る。
落ちるのはプロセスが終わる瞬間なので、同じプロセスの中からは観測できない）。
