# ADR-0024: フォルダを作る・ノートを移す（K-3）

日付: 2026-08-20
状態: 採用（spec §7.1「アプリからは作らせない」を一部改める）

## 文脈

サブフォルダは読む側の全経路（走査・索引・一覧・検索）で動いており、
K-2 でサイドバーにも見えるようになった。見えるのに動かせないのは
片手落ちで、「フォルダへ移動」を求める段階になった。§7.1 の
「手で作ったサブフォルダは読むが、アプリからは作らせない」を改める。

## 決定

1. **入口は「フォルダへ移動…」だけ**（一覧の右クリック）。移動先の
   選択肢に**新しい名前を打てば、その時フォルダが作られる**。
   単独の「新しいフォルダ」メニューは置かない: フォルダツリーは索引
   （ノートのパス）由来なので、空フォルダは作った端から見えない。
   ノートが入って初めて意味を持つ（TASKS K-3 の
   「サイドバーに新しいフォルダ」からの逸脱として記録）
2. **本文は書き換えない（R1）。** 添付リンク（`attachments/…`）は
   アプリ内の解決（image_cache / exporter）が **vault ルート基準**なので、
   ノートがどこへ動いても表示と書き出しは壊れない（実測）。
   他アプリのプレビューはノート基準で解決するため、サブフォルダの
   ノートでは絵が出ないことがある — これは手で作ったサブフォルダに
   置いた時点で既にある制約で、移動が新しく壊すものではない（G3 注記）
3. `[[ノート名]]` は**題名で解決**するので移動しても切れない（確認済み）
4. **空になったフォルダは掃除する。** 移動で元のフォルダが完全に空に
   なったら消し、祖先も空なら root の手前まで遡って消す。中に何かが
   1 つでもあれば触らない
5. **取り消しは提供しない。** ファイルの移動はテキスト Undo の外にある。
   もう一度「フォルダへ移動…」すれば戻せる（移動先は通知に出す）
6. 移動先のガードは `_writable_folder`（vault の外・予約フォルダ
   `.trash` / `.hitofude` / `templates` / `attachments` を拒む）。
   フォルダ名は各セグメントを `sanitize_filename` で整える
7. 履歴（ADR-0023）の鍵: front matter に id があるノートは移動しても
   鍵が変わらず履歴が繋がる。id の無い手作りノート（`path:` 鍵）は
   移動で鍵が変わり履歴が途切れる — 既存の改名と同じ制約

## 追記（2026-08-21）: フォルダを直接作れるようにした

決定 1 の「入口は『フォルダへ移動…』だけ」を改める（ユーザー要望）。
サイドバーのフォルダを右クリック →「新しいフォルダ…」で、その中に
フォルダを作れる（「直下」からは vault 直下に作る）。

**同時に、フォルダの一覧をディスクから引くようにした。** 索引（ノートの
パス）由来だと空フォルダが見えず、「作ったのに出てこない」になる。
件数は索引（速い）、存在はディスク（`Vault.folders`）が決める。索引に
あってディスクに無いものは出さない（R9: 真実はファイル側）。

## 追記 2（2026-08-21）: 空フォルダは残す

決定 4（空になったフォルダの掃除）を**取り消す**（ユーザー決定）。
フォルダは「作るもの・管理するもの」になったので、最後のノートを移した
だけで消えると「勝手に無くなった」になる。

- ノートの移動・ゴミ箱送りで、**元のフォルダは空でも残す**
- 消す出口はサイドバーの右クリック「フォルダを削除…」。**ノートが
  1 つでも入っていたら消さない**（フォルダの削除にゴミ箱は無いので、
  中身ごと消える操作は用意しない）。中が空フォルダだけなら消せる。
  macOS が置く `.DS_Store` は空の判定で無視する
- 「直下」（保管フォルダそのもの）には削除を出さない
- `.trash` の中の階層（復元のための裏側）は今まで通り空の殻を残さない。
  `_prune_empty_dirs` はゴミ箱専用になった

## 影響

- spec §7.1 の該当文言をこの ADR で上書きする（フォルダ作成は
  「移動の副産物」としてのみ許す）
- `Vault.create(folder=)` の `mkdir(parents=True)` はこの決定で正当化
  される（K-2 レビューで指摘された「ADR なしのフォルダ作成能力」）
