# ADR-0004: 本文中の画像は「文字の大きさ」で高さを作る

- 状態: 採用
- 日付: 2026-08-09
- 関連: R4（マーカーの隠蔽）, R5 / ADR-0002（`QTextBlockFormat` を使わない）, §6.6

## 背景

`QPlainTextEdit` は画像を持てない。本文中に画像を出すには、
**行の高さを確保して `paintEvent` で描く**しかない。
高さを作る手段が R5 と衝突しないかが問題だった。

## 決定

### 1. 高さは `setFontPointSize` で作る

`QTextBlockFormat` は使わない（R5）。R4 がマーカーを潰すのに使っている
「文字の大きさ」というレバーを**逆向きに**使う。

実測（`QSyntaxHighlighter.setFormat` 経由）:

| | |
|---|---|
| 行の高さ | pt に比例して伸びる |
| 本文 | 変わらない |
| 他の行 | 影響なし |
| Undo スタック | **消費しない** |

最後の 1 点が決め手。ADR-0002 が `QTextBlockFormat` を却下した理由は
「効果がゼロ」と「Undo を 1 段消費する」の 2 つで、こちらはどちらにも
当たらない。

### 2. 大きくするのは 1 文字だけ

行全体を大きくすると、リンク文字列が横に伸びて折り返し、高さが跳ねる。

| pt | 行全体を大きくした場合 |
|---|---|
| 60 | 99px |
| 120 | 197px |
| 240 | **788px**（折り返し） |
| 480 | **2361px** |

`![](...)` を 0.5pt に潰したうえで**先頭 1 文字だけ**を大きくすると、
20〜400pt で比が一定になり、窓幅にも依存しなくなる。

### 3. pt と px の比は実行時に測る

`QFontMetricsF.height()` は**予測に使えない**。同じ pt でも実際の行高との比が
フォントごとに違う（実測）。

| フォント | 実際の行高 / `fm.height()` |
|---|---|
| Hiragino Sans | **1.500** |
| Menlo | 1.005 |
| Helvetica | 1.000 |
| Arial | 1.030 |

そのため `QPlainTextDocumentLayout` を持つ捨て `QTextDocument` を 1 つ組んで
実測し、フォントごとに 1 回だけ覚える（`highlighter.line_height_ratio`）。

### 4. カーソルを入れても記号を出さない

他のマーカーと同じ「中に入ると記号が現れる」を当てると、行高が縮んで
**下の全部が飛び上がる**。`docs/manual_test.md` §2 の
「行の高さが変わらない」約束を破る。

画像は「記号を隠している」のではなく「別の見え方をしている」もので、
`**強調**` とは性質が違う。パスを直したいときは `Cmd+/`（ソースモード）で
生の Markdown に戻せる。

### 5. 縮小結果は必ずキャッシュする

| | |
|---|---|
| 毎回 読み込み＋縮小 | 21.35ms |
| キャッシュ済みを 1 枚 | 0.05ms |
| キャッシュ済みを 20 枚 | 1.05ms |

3024x1964 の PNG 1 枚で §6.6 の 16ms を単独で超える。キャッシュは
最適化ではなく**成立条件**。`(パス, mtime, 表示幅)` を鍵にする。

## 帰結

- 画像入りのノートでも打鍵 → 再描画は p95 4.46ms（基準 16ms）
- 読めない画像は記号ごと見せる。潰すと**空行にしか見えず**、壊れたことに
  気づけない
- 対象は「行まるごとが画像 1 つ」だけ。文中の画像は行の途中に高さを作る
  別の難しさがあり、実用上ほぼ「1 行 1 画像」なので切った
- 保管フォルダの外は読まない。本文は手で編集できるので、`../` や絶対パスで
  任意のファイルを開かせない（`editor/exporter.py` と同じ判断）
