# ADR-0004: 本文中の画像は「文字の大きさ」で高さを作る

- **日付**: 2026-08-09
- **状態**: 採用
- **覆す対象**: spec.md §4.1「画像は v1 ではリンクとして扱い、インライン画像は
  v1.1 で `QTextEdit` への移行と合わせて再検討する」および技術比較表の
  「画像のインライン表示 `QPlainTextEdit`: ×」

## 背景

`QPlainTextEdit` は画像を持てない。仕様書はそれを理由に、インライン表示を
v1.1 へ送り、**`QTextEdit` への移行とセット**で考えていた。

しかし移行は R1〜R8 の前提（ソース文字列が唯一の真実、マーカーの隠蔽、
位置とオフセットの 1:1）を全部やり直す話になる。移行せずに済むなら、
そのほうがはるかに安い。

本文中に画像を出すには**行の高さを確保して `paintEvent` で描く**しかなく、
高さを作る手段が R5（`QTextBlockFormat` を使わない）と衝突しないかが
最後の関門だった。

## 決定

`QTextEdit` へ移行せず、`QPlainTextEdit` のままインライン表示する。

1. **高さは `setFontPointSize` で作る。** R4 がマーカーを潰すのに使っている
   「文字の大きさ」というレバーを逆向きに使う。`QTextBlockFormat` は使わない
2. **大きくするのは先頭 1 文字だけ。** `![](...)` は 0.5pt に潰す
3. **pt と px の比は実行時に測る。** `QPlainTextDocumentLayout` を持つ捨て
   `QTextDocument` を 1 つ組んで実測し、フォントごとに 1 回だけ覚える
   （`highlighter.line_height_ratio`）
4. **カーソルを入れても記号を出さない。** 画像だけ他のマーカーと別扱いにする
5. **縮小結果は必ずキャッシュする。** `(パス, mtime, 表示幅)` を鍵にする

対象は「行まるごとが画像 1 つ」だけ。文中の画像は扱わない。

## 根拠

**1 について。** `QSyntaxHighlighter.setFormat` 経由で実測した。

| | |
|---|---|
| 行の高さ | pt に比例して伸びる |
| 本文 | 変わらない |
| 他の行 | 影響なし |
| Undo スタック | **消費しない** |

最後の 1 点が決め手。ADR-0002 が `QTextBlockFormat` を却下した理由は
「効果がゼロ」と「Undo を 1 段消費する」の 2 つで、こちらはどちらにも
当たらない。

**2 について。** 行全体を大きくすると、リンク文字列が横に伸びて折り返し、
高さが跳ねる。

| pt | 行全体を大きくした場合 |
|---|---|
| 60 | 99px |
| 120 | 197px |
| 240 | **788px**（折り返し） |
| 480 | **2361px** |

先頭 1 文字だけにすると、20〜400pt で比が一定になり、窓幅にも依存しない。

**3 について。** `QFontMetricsF.height()` は予測に使えない。同じ pt でも
実際の行高との比がフォントごとに違う。

| フォント | 実際の行高 / `fm.height()` |
|---|---|
| Hiragino Sans | **1.500** |
| Menlo | 1.005 |
| Helvetica | 1.000 |
| Arial | 1.030 |

**4 について。** 他のマーカーと同じ「中に入ると記号が現れる」を当てると、
行高が縮んで**下の全部が飛び上がる**。`docs/manual_test.md` §2 の
「行の高さが変わらない」約束を破る。画像は「記号を隠している」のではなく
「別の見え方をしている」もので、`**強調**` とは性質が違う。パスを直したい
ときは `Cmd+/`（ソースモード）で生の Markdown に戻せる。

**5 について。** 3024x1964 の PNG 1 枚で §6.6 の 16ms を単独で超える。

| | |
|---|---|
| 毎回 読み込み＋縮小 | 21.35ms |
| キャッシュ済みを 1 枚 | 0.05ms |
| キャッシュ済みを 20 枚 | 1.05ms |

キャッシュは最適化ではなく**成立条件**。

## 影響

- **`QTextEdit` への移行が不要になった。** R1〜R8 の前提を保ったまま
  インライン表示が成立する。§4.1 の「v1.1 で移行して再検討」は不要
- 画像入りのノートでも打鍵 → 再描画は p95 4.46ms（基準 16ms）
- 読めない画像は記号ごと見せる。潰すと**空行にしか見えず**、壊れたことに
  気づけない
- 文中の画像は行の途中に高さを作る別の難しさがあり、実用上ほぼ
  「1 行 1 画像」なので切った
- 保管フォルダの外は読まない。本文は手で編集できるので、`../` や絶対パスで
  任意のファイルを開かせない（`core/paths.py` に統一）
