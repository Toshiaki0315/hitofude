# ADR-0016: 囲みの飾りと本文の隙間は documentMargin で作る

- **日付**: 2026-08-18
- **状態**: 採用
- **覆す対象**: なし（ADR-0003 の実測値「71 桁」を更新する）

## 背景

`:::note` と引用の縦バー、コードブロックの背景は `paintEvent` で描く
（ADR-0002）。飾りは **viewport の左端（x=0）から**描くのに対し、本文は
`QTextDocument.documentMargin` のぶん右から始まる。既定の 4px では、

- 縦バー（`LEFT_INSET=2` から幅 4px = x=2..6）が本文（x=4 から）に**重なる**
- コードブロックの背景と中身の間に余白が無い

という状態だった（実測）。ユーザーから「`:::` や ``` で囲んだときに左側へ
少しマージンが欲しい」という要望が出た。

**本文を右へ動かす道は無い。** ブロックの左余白は `QTextBlockFormat` しか
手段がなく、R5（ADR-0002）でそれは使えない（`QPlainTextDocumentLayout` が
ブロック書式を完全に無視し、適用すると Undo を 1 段消費する）。

## 決定

`documentMargin` を既定の 4px から **12px** に広げる
（`editor_widget.CONTENT_MARGIN`）。飾り側の座標は**一切変えない**。

この値がそのまま「飾りと中身の隙間」になる:

| 見えるもの | 隙間 |
|---|---|
| コードブロックの背景の左端 → 中身 | 12px |
| `:::note` / 引用の縦バーの右端 → 中身 | 6px（バーは x=2..6） |

## 根拠

- 飾りの座標を触らずに済む。1 つの定数で「余白」と「隙間」が連動する
- 本文の上下にも同じ余白が付き、1 行目が窓の縁から離れて読みやすくなる
- 深い引用（depth 2 以上）のバーは従来どおり中身に重なる。バーは
  `QUOTE_BAR_STEP=10` ずつ右へ進み、帯（12px）を超えるため。これは
  ADR-0002 以来の既知の見え方で、この決定で悪化はしていない

## 影響

- 本文の使える幅が 8px 狭くなる。**表の上限が 71 桁 → 69 桁**（半角換算。
  日本語 35 → 34 文字）になった。ADR-0003 が記録している「71 桁」は
  `documentMargin=4` 当時の実測値として読むこと
- 同梱マニュアルの「書き出し」の表が 69 桁に収まらなくなったので、
  セル内の強調（`**`）を外して縮めた。表示では隠れる記号だが、
  `core.table.fits` は桁数に数える（安全側の過大評価）
- 画像の最大幅が 712px → 696px
- 回帰テスト: `tests/editor/test_painter_overlay.py::TestBlockInset`
  （背景・縦バーが中身に重ならないこと）


## 追記（2026-08-26）: 12px → 24px

「ノート本文の左右のマージンをもう少し広げてください」（ユーザー要望）。
本文の左右を沈んだ色にした（Q-1）ことで、**本文が紙の縁に近いことが
かえって目に付く**ようになった。

**この決定の骨格は変えていない。** 飾りの座標は今までどおり viewport の
左端から。広げたのは同じ 1 つの定数だけで、「余白」と「隙間」が連動する
性質もそのまま。

| 見えるもの | 隙間（前 → 後） |
| --- | --- |
| コードブロックの背景の左端 → 中身 | 12px → **24px** |
| `:::note` / 引用の縦バーの右端 → 中身 | 6px → **18px** |

**表が崩れる心配は無くなっている。** この ADR を書いた当時は桁数が足りない
と表として描かれなかったが、ADR-0028 / 0029 で**収まらなければ折り返す**
作りになった。使える幅が 24px 減っても、列が少し細くなるだけ。

**値を固定する試験を足した**（`TestContentMargin`）。12 → 24 に変えても
試験が 1 つも落ちず、**変えたことに誰も気づけなかった**ため。
最初は `CONTENT_MARGIN` と比べる形で書いたが、定数どうしの比較になって
変異が素通りしたので、**数を直に書いた**。
