# ADR-0025: 手元の LLM でノートを読む（これから L）

日付: 2026-08-22
状態: 採用（新しい層を 1 つ増やす。spec §6.1 のモジュール表に追記が要る）

## 文脈

書いた文書をレビューさせたい・要約させたい・関連する記述を探させたい
（ユーザー要望）。**渡した資料だけを見る**もので、NotebookLM の簡易版に近い。

外へ出す選択肢は最初から無い。ノートは手元の `.md` が真実（R1）で、
**それを他人のサーバへ送る機能はこのアプリの前提と噛み合わない**。
手元で動かす前提で、実行の器を 2 つ比べた。

|                      | Ollama（別プロセス）             | llama-cpp-python（同プロセス）       |
| -------------------- | -------------------------------- | ------------------------------------ |
| `.app` への影響      | 依存は HTTP だけ                 | ネイティブ拡張と `.dylib` が増える   |
| 落ちたとき           | 無応答で済む                     | **Qt ごとプロセスが飛ぶ**            |
| `core/` の純度（R3） | 保てる（相手は HTTP）            | ネイティブに縛られる                 |
| テスト               | 応答を差し替えるだけ             | CI にモデルの実体が要る              |
| 利用者の手間         | **別途インストールが要る**       | 不要                                 |

## 決定

1. **Ollama を使う。** 決め手は 2 つ。**(a) `.app` を難しくしない** —
   py2app では F-6 で 2 回踏んでいる（PIL の本体が入らない／署名済みの
   `.dylib` を壊して `codesign` が止まる）。残る唯一のタスクが署名と公証
   なのに、そこへ GPU 付きのネイティブ拡張を持ち込まない。
   **(b) 巻き込まれない** — in-process のモデルが abort すれば Qt ごと
   落ちる（exit 139 を追った実績がある）。別プロセスなら最悪でも無応答
2. **モデルは同梱しない。** 4bit の 4b でも 3.3GB、12b で 8GB あり、
   配布物に入る大きさではない。入手と更新は Ollama に任せる
   （入れ方とメモリ別の選び方は [ollama.md](../ollama.md)）
3. **`127.0.0.1` にしか繋がない。** 送り先はコードに埋め、設定でも
   変えられないようにする。**外へ出ないことがこの機能の前提**なので、
   ここだけは緩めない（テストで固定する）
4. **無ければ機能ごと畳む。** Ollama が動いていなければメニューを
   灰色にし、押せない理由と入れ方を案内する。**押してから断らない**
   （G-3 のゴミ箱と同じ作法）
5. **本文は書き換えない（R1）。** 答えは別のペインに出す。本文へ入れるのは
   押されたときだけ。「レビュー」も指摘を並べるだけで、直しはしない
6. **打鍵の経路に入れない（§6.6）。** 生成は `QThreadPool` の別スレッドで
   回す（`IndexSyncTask` / `StatsTask` と同じ形）。答えは流れてきたぶんから
   順に出す（最初の 1 文字まで数秒あり、黙って待たせない）
7. **どのノートを見て答えたかを示す**（L-2 以降）。根拠を確かめられない
   要約は使えない。出典は押せば開く（`open_and_select`）
8. **層の分け方**: `core/llm.py`（GUI 非依存。プロンプトの組み立てと
   Ollama への口。R3 を守る）と `ui/assistant_pane.py`（出す側）。
   **`storage/` には置かない**（保存するものではない）

## 既定値（変えられるようにするが、まずこれで出す）

| 何             | 値                     | 理由                                                     |
| -------------- | ---------------------- | -------------------------------------------------------- |
| モデル         | `gemma3:4b`            | 実測 12.8 秒／要約 1 本。1b は日本語が壊れる（ollama.md） |
| 文脈長         | 8,192                  | 日本語 1 万字強。既定の 4k では長いノートが黙って切れる   |
| ポート         | 11434                  | Ollama の既定。設定で変えられる（追記）                   |
| 待ちの上限     | 120 秒                 | 12b 級で長いノートを読ませても届く                       |
| 送り先         | `http://127.0.0.1:11434` | 変更不可                                                 |

## 結果

- ノートを読ませて要約・レビューできる。**ネットに出ない**
- 利用者は Ollama を別途入れる必要がある。入れない人には**機能が見えない**
  だけで、エディタの動きは何も変わらない
- 依存が 1 つも増えない（HTTP は標準ライブラリで足りる）
- モデルが遅い・答えが悪いという不満は**モデル選びの問題**に切り分けられる
  （アプリを直さずに `ollama pull` で変えられる）

## 追記（2026-08-22）: 設定に出したもの

モデルを選びたい・別のポートで動かしている、という要望が出た。**送り先を
そのまま設定に出すことはしない**（決定 3 は変えない）。分けて考える。

| 何             | 設定に出すか | 理由                                                   |
| -------------- | ------------ | ------------------------------------------------------ |
| モデル         | **出す**     | 手元にあるものは人それぞれ。`ollama list` を候補に出す |
| ポート         | **出す**     | `OLLAMA_HOST` で別のポートにしている人がいる           |
| 渡す量（文脈） | **出す**     | メモリと引き換え。32GB なら広げられる                  |
| 送り先の機械   | **出さない** | ここを開けると**ノートを外へ送る道**ができる           |

**ポートは「どこへ送るか」を変えない。** 相手は `127.0.0.1` のままで、
同じ機械の別の窓口を指すだけ。決定 3 の「外へ出さない」は保たれる。
画面にも `（送り先は 127.0.0.1 に固定）` と出して、誤解を残さない。

モデル名は**候補から選べて、打つこともできる**（これから `ollama pull`
するモデルを先に書いておける）。**空にはできない**（空のまま保存できると、
押しても何も起きないアプリになる）。

## 追記（2026-08-22）: 呼び方を「ローカルLLM」に揃えた

この文書では「手元の LLM」と書いているが、**画面と使い方のノートは
「ローカルLLM」で揃えた**（ユーザー決定）。設定の選択肢に
「ローカルLLM」と出した以上、説明が別の言葉だと探せない。
見張りは `tests/ui/test_wording.py`。

## 追記（2026-08-23）: 別マシンの Ollama は SSH トンネルで

「デスクトップの大きなモデルを使いたい」という要望が出た（ユーザー）。
**送り先の欄は出さない**（決定 3 は変えない）。代わりに **SSH トンネル**を
案内する（`docs/ollama.md`）。手元のポートを向こうへ繋ぐので、アプリから
見た送り先は `127.0.0.1` のままで済む。

**アプリの変更はゼロ。** 既にあるポート設定で足りることを実測した
（11500 番へ転送して要約が通った）。しかも素の URL 欄より安全で、
**通信が暗号化され、認証が SSH の鍵で行われ、受け側を外に開かなくてよい**
（Ollama に認証は無く、通信も平文 HTTP）。

素の URL 欄を出す案の危うさも書き残す。**打ち間違い 1 回でどこへでも
送れる**（Ollama 互換の口はクラウドにもある）ので、「LAN の中だけ」を
守れない。開けるとしたら**私設アドレス限定＋送り先の常時表示**が要る。

## やらないこと

- **自動で走らせない。** 開いただけ・打っただけで生成しない。GPU が回り、
  電池が減り、何より**頼んでいない処理を裏でやらない**
- **本文の自動修正。** R1 の柱を曲げるうえ、直した理由が残らない
- **外部 API（OpenAI 等）への切り替え口。** 作れば「うっかり外に出す」道が
  できる。必要になったらその時に ADR を書く

## 追記（2026-08-24）: 待ち時間は設定で変える／時間切れはそう言う

大きいモデルで「Ollama に繋がりませんでした」と出る、という報告
（ユーザー）。実測すると**繋がっていて、待ち時間を超えていた**。

| モデル | 最初の 1 行まで | 一言の返答が終わるまで |
| ------ | --------------- | ---------------------- |
| gemma3:12b | 7.8 秒 | 5.5 秒 |
| qwen3.5:9b | 3.6 秒 | 176.3 秒 |
| gemma4:26b | **391.9 秒** | （測っていない） |

`urlopen` の待ちは「次の 1 行が届くまで」なので、読み込みに時間が
かかるモデルでは最初の 1 行の前に切れる。決めたこと:

1. **待ち時間を設定に出す**（`llm/timeout_minutes`。既定 10 分、1〜60 分）。
   手元のモデルによって桁が違うので、既定 1 つでは決められない
2. **時間切れを `TimedOut` として分ける**（`NotRunning` と混ぜない）。
   画面には「◯分待っても答えが返りませんでした。大きいモデルは
   読み込みだけで数分かかります（設定で延ばせます）」と出す。
   動いているのに「動いているか確かめてください」は嘘になる
3. **読み込み中はそう言う**（`/api/ps` に載っていなければ
   「読み込んでいます…」）。6 分の沈黙は壊れて見える
4. 居るかの確認（`available` / `models` / `/api/ps`）は**待ち時間を
   引きずらない**（3 秒のまま）。起動時と `Cmd+,` から GUI スレッドで
   呼ぶので、ここを延ばすと窓が固まる
