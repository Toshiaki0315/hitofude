# ADR-0029: 表は本文と同じフォントで、常に描画側が組む

日付: 2026-08-25
状態: 採用（ADR-0003 の「表は BIZ UDGothic」を置き換え。ADR-0017 の
描画機構を表の全部に拡張）

## 文脈

表だけ別フォント（BIZ UDGothic）で、本文（Hiragino Sans）と並ぶと
浮いて見える（ユーザー要望）。等幅だったのは桁揃えの都合で、
「全角＝半角のちょうど 2 倍」という性質に、ソースの `|` 位置＝罫線の
x 座標という設計が全面的に依存していた（ADR-0003）。

## 決定

**列の位置を桁数ではなくピクセルで決め、表は常に描画側（paintEvent）が
本文フォントで組む。**

1. core の折り返し関数（`wrap_cell` / `wrapped_columns` / `wrap_row`）に
   **測り係（`measure`）を注入**できるようにした。既定は従来の表示幅
   （桁数）で、描画側は `QFontMetricsF` のピクセル実測を渡す。
   core は Qt を知らないまま（R3）
2. ハイライタは表のすべての行を隠して高さを予約する（ADR-0017 の機構。
   これまでは収まらない表だけだった）。列幅・折り返しは本文フォントの
   実測で決める
3. キャレットを入れた行は生の Markdown に戻って編集できる（従来どおり）。
   生の行の高さは描画行と揃える（`_pad_cells` が比例計算で合わせる）
4. **整列記法（`:---:` `---:`）を画面でも効かせる。** プロポーショナルでは
   数字の右揃えが自然には起きないため、描画側がセルごとに寄せる
5. 「幅に収まるか」の分岐（`fits`）は表示から消えた。列は自然幅
   （断片の最長）で組み、余っても間延びさせず、足りなければ広い列から
   縮めて折り返す

## 引き換えに変えたこと

- **クリックの手触り**: 収まる表でも、クリックした行は生の Markdown に
  開いてから編集になる（折り返し表だけだった挙動が全表に。ユーザー了承）
- ソースの `|` 揃え（整形）は従来どおり表示幅（桁数）基準。**ソースの
  行儀**の話であって、画面のレイアウトとは独立になった

## 副産物

- **CI のフォント段取りが丸ごと不要になった。** BIZ UDGothic を
  ランナーに配る仕掛け（つい先日入れたもの）・門番テスト・conftest の
  プロセス内登録を撤去。「全角＝半角×2」という環境依存の前提そのものが
  消えたため
- 等幅では見えなかった「列の間延び」が消え、狭い表は狭く出る
