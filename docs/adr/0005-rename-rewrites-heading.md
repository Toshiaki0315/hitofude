# ADR-0005: 「名前を変更」は本文の見出しを書き換える

- **日付**: 2026-08-09
- **状態**: 採用
- **覆す対象**: なし。spec.md §7.1「タイトル変更時はファイルをリネームする」と
  §7.2「タイトルは最初の H1 →…」を**補う**（UI の「名前を変更」がどちらを
  変えるべきかは仕様書に書かれていない）

## 背景

一覧に出るタイトルは**本文から導かれる**（`document.title_of`）。

    最初の H1 → 無ければ最初の非空行 → 無ければファイル名

そのため「名前を変更」でファイル名だけを変えても、**一覧の表示は変わらない**。
ユーザーから見ると「名前を変えたのに変わらない」ことになる。

## 決定

**本文の見出しを書き換える。** `core/document.with_title()` が `title_of()` の
探し方を裏返す。

- 見出しがあれば、その**行の文字だけ**を差し替える。深さ（`#` の数）は保つ。
  文書の構造を勝手に変えない
- 見出しが無ければ本文の先頭に `# タイトル` を**足す**。段落を書き換えると
  文章が消えるが、上に足すだけなら何も失わない
- front matter は触らない

ファイル名は保存時に見出しへ追従する（`_rename_if_title_changed`）。
ファイル名に使えない文字（`/` や `:`）は**ファイル名側だけ**置き換える。
本文の見出しには打った通り入る。

    「定例ミーティング 1/15」 → 見出し: # 定例ミーティング 1/15
                              ファイル: 定例ミーティング 1-15.md

## 根拠

| 案 | 内容 | 問題 |
|---|---|---|
| A | ファイル名だけ変える | 表示が変わらない。タイトルの出どころが 2 つになる |
| B | **本文の見出しを書き換える** | 本文を編集する。見出しの無いノートの扱いを決める必要がある |

R1 が「ソース文字列が唯一の真実」と定めている以上、タイトルの真実も本文にある。
ファイル名を独立させると真実が 2 つになり、どちらが正しいか決められなくなる。

**A は実装が最も簡単だが、「一覧の表示が変わらない名前の変更」はユーザーから
見て壊れている。** `2026-08-08-会議.md` のように意図して別名を付けたい用途は、
Finder で直接リネームすれば満たせる。その場合 `_rename_if_title_changed` は
追従しないので、付けた名前は保たれる。

## 影響

- **開いているノートはエディタ経由で書き換える。** 本文の編集なので、
  打ち間違えたら `Cmd+Z` で戻せるべき。1 回の編集にまとめる
- 開いていないノートはファイルを直接書き換えて索引を更新する
- 見出しの無いノートは**見出しが増える**。驚きはあるが、何も失わない側に倒した
- ゴミ箱の中では出さない。既に削除済みのノートの名前を変える意味がない
