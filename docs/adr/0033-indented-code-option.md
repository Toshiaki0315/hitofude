# ADR-0033: 4 字下げのコードブロックを設定で切れるようにする

- 日付: 2026-08-28
- 状態: 採用
- 決めた人: ユーザー（要望）／実装は Claude

## 背景

ユーザーから「半角 4 文字を字下げした時にコードブロックのようになるのは
仕様ですか？」と問われた。**仕様である**——仕様書 §1.3 が

> *記法* は **CommonMark + GFM 拡張**を基準とし、**保存形式も素の Markdown とする**

と定めており、字下げのコードブロック（indented code block）は CommonMark の
中核記法だからだ。実装も意図的で、文脈の条件まで作り込まれている
（空行のあと・リストの外・タブは 4 桁）。

続けて「設定で on/off を決められるといい。既定は on で問題ない」との要望。

## 決定

**設定で切り替えられるようにする。既定は on（今までどおり）。**

- `Config.indented_code`（`editor/indented_code`、既定 `True`）
- 設定 → 本文の見え方 →「4 文字の字下げでコードブロックとする」
- 切ると、**画面も書き出しも**字下げを段落として扱う

## なぜ

**この記法は貼り付けで意図せず発動する。** 他所からインデントされた文章を
貼ると、書き手にその気がなくてもコードブロックに化ける。Qiita・Notion・
Slack はまさにこの理由で廃止しており、実際に踏む人がいる記法である。

一方で、**外から持ち込んだ `.md` の見え方が変わる**副作用がある。既定を
on に置くのはそのため——CommonMark 準拠のままで、困った人だけが外す。

## 仕様書との関係

§1.3 の「CommonMark 基準」を**設定で外せる**ようにするので、方針からの
逸脱にあたる。ただし:

- **既定は準拠したまま。** 何もしなければ今までと同じ
- **保存形式は変わらない**（G3 は無傷）。解釈だけの話で、`.md` は素のまま
- **フェンス（記号で囲むコード）は切らない。** 止めるのは字下げだけ

## 実装

`core/` は設定を知らない（R3）ので、**旗は呼ぶ側が渡す**。

| 層 | 口 |
| --- | --- |
| `core/block_parser` | `parse(text, indented_code=)` / `classify_line(..., indented_code=)` |
| `core/html` | `render(text, indented_code=)` |
| `editor/highlighter` | `set_indented_code()`。**全体を掛け直す**（表示の決まりごと自体が変わるので R7 の例外） |
| `editor/exporter` | 6 つの入口に旗を通す |
| `ui/main_window` | 設定を部品へ流す（起動時と設定変更時） |

markdown-it 側は `disable("code")` で止まる（`code` が**インデント
コードの規則**の名前。フェンスは別の規則なので止まらない）。解析器は
**作り置きする**——打鍵のたびに組むと 1 文字ごとに構築費が乗る（§6.6）。

**画面と書き出しは同じ旗を見る。** 片方だけ切ると、同じノートが画面と
書き出しで違う形になる。

## 分かっていること

- 使い方ノートの `:::note` の見本は**この記法で書かれている**。off にすると
  見本が段落として出る（記号は読めるので実害は小さい）
- 既存のノートの見え方が変わるのは off にしたときだけ
