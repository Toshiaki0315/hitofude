# ADR-0003: 表は罫線を描いて見せる。等幅フォントは BIZ UDGothic を使う

- **日付**: 2026-08-08
- **状態**: 採用
- **覆す対象**: spec.md §1.2 の非ゴール「WYSIWYG な表エディタ（v1 は表を
  『等幅フォント + 罫線揃え』で扱う）」、および §5.2 の等幅フォント指定 `SF Mono`

## 背景

ユーザーから「表を Qiita のように罫線付きで表示できないか」という要望が出た。
実装前に §1.2 の前提を実機で確かめたところ、**前提そのものが成立していなかった**。

### 検証 1: 等幅フォントで日本語の桁が揃わない

`Menlo` をはじめ一般的な等幅フォントは CJK グリフを持たない。日本語部分は
フォールバック先のフォントで描かれ、その全角幅は半角のちょうど 2 倍にならない。

| フォント | 全角 ÷ 半角 | 等幅として成立 |
|---|---|---|
| Menlo | 1.66 | × |
| Courier New | 1.67 | × |
| PT Mono | 1.67 | × |
| Osaka | 1.24 | × |
| Source Han Code JP | 1.50 | × |
| Hiragino Sans | 1.33 | × |
| **BIZ UDGothic** | **2.00** | **○** |

ソースを表示幅で揃えても、画面上の縦線は揃わなかった。4 行の表で `|` の
x 座標が `(4, 212, 469)` `(4, 220, 641)` … とばらつき、行の高さも CJK の
有無で 34px / 24px と異なっていた。

### 検証 2: `SF Mono` は使えない

§5.2 が指定する `SF Mono` は macOS がアプリケーションに公開していない。
Qt が `missing font family` を警告し、解決されないまま別フォントに落ちる。

## 決定

1. **表の行には `BIZ UDGothic` を使う。** macOS 標準で全角:半角 = 2:1 が
   成立する唯一のフォント。コードブロックは `Menlo` のままとする。
2. **`|` と区切り行（`|---|---|`）は隠し、罫線を `paintEvent` で描く。**
   ヘッダ行は太字にし、背景色を敷く。
3. **キャレットが表の中にある間は罫線を描かず、生のソースを見せる。**
4. **表の行から離れたときに自動で桁を揃える。**
5. **セル内の折り返しは実装しない。** 長いセルは折り返さず横に伸びる。

## 根拠

- 2 は §1.2 の非ゴール「WYSIWYG な表エディタ」に**抵触しない**。
  ソース文字列は一切変換せず、`|` を削除もしない。R4 のとおり極小化して
  隠すだけなので、`QTextCursor` の位置とソースのオフセットは 1:1 のまま。
  やっているのは「描画の追加」であって「編集モデルの変更」ではない。
- 3 は §6.4 のリビール条件をブロック単位から表単位へ広げたもの。編集中は
  ソースが揃っておらず、揃った前提で引いた線が本文とずれる。
- 5 が唯一の断念。セル内で折り返すには「ソースの 1 行 = 画面の 1 行」を
  崩す必要があり、`QTextTable` か `QTextEdit` への移行と往復変換を伴う。
  それは §3.3 が「データ破損が構造的に起きる」として却下した方式に戻ること
  になる。表の見た目のためにデータの安全性を下げる取引はしない。

## 追記（2026-08-15）: 幅に収まらない表は生の Markdown を見せる

決定 5 の「**長いセルは折り返さず横に伸びる**」は**成立していなかった**
（ユーザー報告）。`QPlainTextEdit` は幅で折り返すので、長い行は素直に
折り返す。折り返すと「ソースの 1 行 = 画面の 1 行」が崩れ、`|` の x 座標が
折り返し先の行の座標に戻る。実測（viewport 720px）:

| 行           | 表示行数 | 縦線の x           |
| ------------ | -------- | ------------------ |
| ふつうの行   | 1        | `4, 168, 331, 474` |
| 長いセルの行 | 3        | `4, 168, 766, 126` |

`766` は画面の外、`126` は折り返した先の行の座標。ここへ罫線を引いても
表の形を表さない（3 列目が 1 列目の下に回り込んで見えていた）。

**描けないときは描かない。** 収まらない表は罫線とヘッダ背景を出さず、
`|` と区切り行を**そのまま見せる**。キャレットを表に入れたときと同じ
見え方なので、覚えることは増えない。書き出し（HTML / PDF）は今までどおり
本物の表として組むので、**内容は何も失われない**。

判定は `editor/table.fits()`（純関数）に置き、ハイライタと描画の両方が
同じものを見る。2 か所に書くと「記号は隠れているのに罫線が無い」という
最悪の見え方が生まれる。

**本文は最大 720px（spec §5.1）なので、ウィンドウを広げても直らない。**
15pt で **71 桁**（半角換算）が上限。日本語なら 1 行 35 文字ぶん。
収まらないときはセルを短くするしかない。

## 影響

- `hitofude/editor/table.py`（新規）: 表示幅の計算と整形。純関数。
- `editor/highlighter.py`: `TABLE_FAMILIES`、`|` と区切り行の隠蔽、ヘッダの太字。
- `editor/painter_overlay.py`: 罫線とヘッダ背景。
- `editor/editor_widget.py`: 行を離れたときの自動整形。
- `config.py`: 等幅フォントの既定を `Menlo` に変更（`SF Mono` は解決されない）。
- spec §1.2 / §5.2 は本 ADR で置き換えられたものとして読む。
- 制限（セル内の折り返し）は `docs/manual_test.md` に記載。

## 実装中に踏んだこと

- **`Cmd+Option+T` をショートカットにしてはいけない。** macOS では Option が
  文字合成に使われ、`Option+T` は `†` を生む。ショートカットが発火せず、
  選択範囲がその 1 文字に置き換わってデータが消えた。以後、Option を含む
  ショートカットは使わない（テストで固定）。
- 整形中はキャレットが表の中を通るため、その時点のリビール状態で
  ハイライトされた行が残る。R7 により以後掛け直されないので、整形後に
  表の範囲だけ明示的に `rehighlightBlock()` する。
- `blockBoundingGeometry()` は**表示領域の全幅**を返す。そのまま罫線に使うと
  画面の端まで線が伸びる。左右の縦線で挟んだ範囲に収める。
