# ADR-0017: 収まらない表はセルを折り返して描く

日付: 2026-08-19
状態: 採用（ADR-0003 追記 2026-08-15 の「生の Markdown を見せる」を置き換え）

## 文脈

幅に収まらない表は生の Markdown へ落としていた（ADR-0003 追記）。理由は
`QPlainTextEdit` が長い行を幅で折り返し、「ソースの 1 行 = 画面の 1 行」が
崩れて `|` の x 座標に罫線を引けないため。

ユーザーから「セル内で折り返せないか」の問いがあり、当初は
「QTextTable = リッチテキスト化が要る（§3.3 / R1 / R2 と衝突）ので見送り」
と答えた（TASKS これから I-2）。しかしリッチテキスト化を伴わない別解が
あることがスパイクで実証できたため、方針を転換する。

## 決定

**描画側だけで折り返す。ソースには一切触れない。**

1. **高さの予約はハイライタ**（画像の ADR-0004 と同じ手口）。収まらない表の
   行は全文字を 0.5pt に潰し、先頭 1 文字だけを**透明のまま**拡大して
   「折り返し行数 × 等幅フォントの行高 + 余白」の高さを作る。
   文字は実在し続けるので R4（位置 1:1）は無傷。
2. **中身は paintEvent が描く**。ハイライタが `wrap_cell` / `wrapped_columns`
   （core/table.py の純関数）で折り返した結果を `BlockData.wrapped` に載せ、
   描画はそれを等幅フォント（TABLE_FAMILIES）で置く。列の位置は
   桁数 × 字送りで決まる（全角:半角 = 2:1。ADR-0003 と同じ前提）。
3. **折り返すかは表全体で決める**。1 行だけ折り返すと列の線が行ごとに
   ずれる。1 行でも収まらなければ表全体を折り返し表示にする。
4. **リビールは行単位**。キャレットを入れた行だけ生の Markdown（通常の
   行高）に戻り、そのまま編集できる。収まる表の「表全体で罫線を消す」
   とは違うが、折り返し表示では他の行が読める形のまま残るほうが良い。
5. **列幅の配分**: まず自然幅（全行の最長セル）を取り、入り切らなければ
   いちばん広い列から縮める。下限は 6 桁（`MIN_WRAP_COLUMN`）。
   セル内は空白優先で折り、長い連続語は文字単位で割る（CJK は 2 桁）。

## 検証（スパイク実測）

- 予約とリビールの切り替え 0.0ms、スクロール位置は不変（38 → 38）
- `toPlainText()` 不変（R1）、Undo スタック消費 0（R5 の轍を踏まない）
- 行高 20px → 64px（3 行折り返し時）が正しく予約され、下の行が詰まる

## 影響

- 収まらない表も罫線・ヘッダ背景付きの表として読める。生 Markdown 表示は
  キャレットを入れた行と Raw（ソースモード）だけになる
- 表を離れたとき（自動整形と同じフック）に表の行だけ再ハイライトし、
  編集で変わった列幅を他の行へ反映する（R7: 全体再ハイライトはしない）
- 折り返し表示のセルは左揃えで描く（整列記法はソースと書き出しでは
  今までどおり効く）
- `TABLE_FAMILIES` の定義は painter_overlay へ移動（highlighter が
  painter_overlay を import する向きのため。中身は不変）
