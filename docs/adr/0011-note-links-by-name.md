# ADR-0011: `[[ノート名]]` は名前で結び、無ければ作る

- **日付**: 2026-08-15
- **状態**: 採用
- **覆す対象**: 無し（仕様書の範囲外。TASKS.md の E-6 / 旧 C-10）

## 背景

ノート同士を繋ぐリンク。仕様書には無い機能で、「他の Markdown エディタに
あって、ここに無いもの」として挙がった。決めることが 3 つあった。

1. 何で結ぶか（名前 / ID）
2. 行き先が無いときどうするか
3. バックリンクをどこに出すか

## 決定

1. **名前で結ぶ。** `[[会議メモ]]` はタイトルが「会議メモ」のノートを指す
2. **無ければ作る。** `Cmd+クリック` で `# 会議メモ` だけのノートができて開く
3. **バックリンクは本文の下**に畳める帯として出す（ペインを増やさない）

## 根拠

### 名前で結ぶ

このアプリのタイトルは**本文の H1 から導かれ、ファイル名がそれに追従する**
（ADR-0005）。名前はもともと第一級の識別子として扱われている。

ID（`[[01J8XZ...]]`）で結べば題名を変えても切れないが、**書いた本文が人に
読めなくなる。** 手で打つこともできない。ソースが真実（R1）である以上、
ソースが読めることは譲れない。

代償は「題名を変えるとリンクが切れる」こと。これは 2 の決定で和らぐ
（切れた先を押せば作り直せる）。将来、題名の変更に合わせて本文の `[[...]]`
を書き換える手もあるが、**他のノートを黙って書き換えることになる**ので、
やるなら別の決定として扱う。

照合は `core/wikilink.normalize()` で揃える。規則を `sanitize_filename()` と
同じにしたのは、**ファイル名がその規則で作られる**ため。揃えないと
「書いた名前では見つからないノート」ができる。NFC に寄せるのは macOS の
ファイル名が分解された形（`か` + 濁点）で来ることがあるため。

### 無ければ作る

**書いた時点ではまだ無いノートを指すのがふつう**の使い方で、そこから
書き始められることに価値がある。「押しても何も起きない」だと、作るために
一覧へ戻り、題名を打ち直すことになる。

打ち間違いで空のノートができる面はあるが、できたことは画面で分かる
（題名付きで開く）し、`Cmd+Delete` で捨てられる。**何も起きないほうが、
理由が分からないぶん困る。**

### 行き先の有無で色を変えない

Obsidian は未作成のリンクを別の色で出す。**採らない。** 色を変えるには
エディタが vault 全体のタイトルを知る必要があり、他のノートを作った・
消した・改題しただけで**全体を塗り直す**ことになる。これは R7（全体
再ハイライトの禁止）と正面から衝突する。

### バックリンクは本文の下

- **パレット（`Cmd+R` 型）にしない。** 探しに行った人しか見ない。
  バックリンクの値打ちは「気づいていない繋がりに気づく」ことにある
- **右ペインにしない。** 幅の常時負担が割に合わない。3 ペインで既に
  本文は最大 720px に制限されており、4 枚目を足すとどれかが痩せる。
  しかも**大半のノートはバックリンクが 0** で、空の枠が場所を取り続ける
- **本文の下なら幅を取らず、0 件のときは丸ごと消せる。** 脚注と同じ位置感覚

**エディタの文書に文字として入れてはいけない。** `toPlainText()` がその
まま保存内容（R1）なので、ファイルに無い文字が混ざる。`ui/editor_pane.py`
にウィジェットとして積む。

## 影響

- `SpanType.WIKI_LINK` が増えた。`[[` `]]` はマーカーとして隠れ、名前は
  リンクと同じ色になる
- **`[[名前|表示名]]`（別名）は採らない。** 走査規則は `|` を含むものを
  拾わないので、書いてもただの文字として残る（中途半端に拾って名前が
  壊れるほうが悪い）
- 同じ題名のノートが 2 つあるときは一覧で上に来るほうを開く。**選ばせない**
  （押した人が期待するのは「飛ぶ」ことで、選択肢を出すと流れが切れる）
- 索引に `links` テーブルが増える（バックリンクを引くため）。R9 のとおり
  捨ててよいキャッシュで、`.md` から再構築できる
