# ADR-0023: 版の履歴を vault の中に持つ

- **日付**: 2026-08-20
- **状態**: 採用
- **関係する不可侵ルール**: R1（ソース文字列が唯一の真実）、R9（`.hitofude` は捨ててよいキャッシュ）

## 背景

今の保全は**ゴミ箱（30 日）と自動保存の復帰**だけで、「昨日の状態に戻す」が
できない。書き換えて上書き保存したあと、前の文章は取り戻せない。

外部エディタや Git を併用している人は自力で戻せるが、**このアプリだけで
完結する人には戻す手段が無い**。

ユーザー要望（提案 6）。

## 決定

**保存のたびに、その時点の全文を `.hitofude/history/` へ 1 ファイルとして
残す。** ただし版を増やしすぎないよう間引き、古いものは自動で捨てる。

```
HitofudeNotes/
├── 会議メモ.md                     ← 真実（R1）
└── .hitofude/
    ├── index.sqlite                ← 捨ててよい（R9）
    └── history/
        └── 01M0.../                ← ノートの id（front matter の ULID）
            ├── 2026-08-19T09-12-30.md
            └── 2026-08-20T06-15-49.md
```

| 決めたこと | 内容 |
| --- | --- |
| 単位 | **全文をそのまま置く**（差分にしない） |
| 置き場 | `.hitofude/history/<ノートの id>/<日時>.md` |
| 残す間隔 | 直前の版から **5 分**以上経っていれば残す |
| 保つ数 | 1 ノートにつき **50 版**まで |
| 保つ期間 | **30 日**（ゴミ箱と揃える） |
| 戻し方 | 戻す前に**今の内容を 1 版残してから**書き戻す |

## 根拠

- **差分にしない。** 差分はそれ自体が壊れうる構造で、壊れたときに何も
  戻せなくなる。ノート 1 つは数 KB で、50 版でも数百 KB。**素の `.md` の
  ままなら、アプリが無くても Finder から開いて読める**（R1 の精神）
- **id で分ける。** 題名（＝ファイル名）は変わる。id は front matter の
  ULID で不変なので、名前を変えても履歴が途切れない
- **5 分間隔。** 自動保存は打ち終わって 0.8 秒で走るので、1 版/保存にすると
  1 時間の執筆で数百版になる。5 分なら「気づいたら消していた」を取り戻せる
  粒度で、かつ 1 日の執筆でも十数版に収まる
- **戻す操作も版に残す。** 戻したあとに「やっぱり戻す前がよかった」と
  言えるようにする。取り消せない操作を増やさない
- **`.hitofude/` の中に置く。** vault と一緒に運ばれる（iCloud・バックアップ・
  別マシンへの持ち出しで履歴も付いてくる）。隠しフォルダなので `scan()` の
  対象外で、一覧にも検索にも出ない

## R9 との関係（ここを変える）

R9 は「`.hitofude/index.sqlite` は捨ててよいキャッシュ」と言っている。
**履歴は捨てると戻せない。** R9 の対象を「索引」に限る旨を CLAUDE.md に
書き足す。

`.hitofude` ごと消す操作は、これまで「索引が作り直されるだけ」だったが、
これからは**履歴も失う**。マニュアルにもそう書く。

## 影響

- 新しいファイル: `storage/history.py`（Qt を知らない）、`ui/history_dialog.py`
- 保存の道（`ui/save_controller._save`）から 1 行呼ぶ
- 掃除は起動時（ゴミ箱の `purge_trash` と同じ場所）
- 容量は増える（実測）:

  | ノートの大きさ | 50 版ぶん |
  | --- | --- |
  | 500 文字（ふつうのメモ） | 69KB |
  | 5 万文字（長い記事） | 6.3MB |

  ふつうのメモなら 100 本書いても 7MB 程度。長い記事を毎日書き換える人は
  数十 MB になるので、`storage/history.total_bytes()` で出せるようにしてある

## 追記（2026-08-24）: 間隔を選べるようにした

`MIN_INTERVAL_MINUTES = 5` は「打ちながら数百版にならない」ための下限として
決めたが、**どれくらい細かく残したいかは書く人によって違う**（ユーザー要望）。
設定に「履歴を残す間隔」を出し、**なし / 5 / 15 / 30 / 60 分**から選べるように
した（既定は今までと同じ 5 分）。

- 判断は `storage/history.keep(interval_minutes=…)` に残す（Qt を知らない層のまま）
- 「なし」（`0`）は自動では残さない。**`Cmd+S` を押したときだけ 1 版残す**
  （押したことを `flush(explicit=True)` で伝える）
- **本文の保存は変えない。** 打ち終わって 0.8 秒後に書く（§7.4）。
  ここで変えるのは版を残す間隔だけで、「なし」でもノートは自動保存される

ユーザーの当初の要望は「編集中の自動保存の間隔を選びたい」だったが、
本文の書き込み間隔を分単位にすると、落ちたときに失う量がその間隔ぶんに
なる。どちらを変えたいのか確認したうえで、履歴側の間隔と決めた。
