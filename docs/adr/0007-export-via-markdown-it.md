# ADR-0007: 書き出しは markdown-it-py で描く

- **日付**: 2026-08-10
- **状態**: 採用
- **覆す対象**: spec.md §9 Phase 6「HTML / PDF エクスポート（**ここでのみ
  `QTextDocument.setMarkdown()` を使ってよい**）」および §3.3 の結論
  「`setMarkdown()` は読み取り専用のエクスポート/プレビュー用途に限定する」の
  **前半だけ**。「編集モデルには絶対に使わない」は変わらない（むしろ強まる）

## 背景

Mermaid・数式・Qiita 記法（TASKS.md の B-3〜B-5）を検討して、**どれも
書き出しの手前で死ぬ**ことが分かった。原因は共通で、書き出しが
`QTextDocument.setMarkdown()` を通っていることにある。

実測（`setMarkdown()` に通して `toHtml()` を見た）:

| 書いたもの                   | 結果                                    |
| ---------------------------- | --------------------------------------- |
| ` ```mermaid `               | 情報文字列ごと消える。言語が残らない    |
| ` ```js:index.js `           | 同上。ファイル名が消える                |
| 生の `<div class="mermaid">` | タグごと消える                          |
| `:::note info`               | ただの段落。**改行まで潰れる**          |
| 脚注 `[^1]`                  | `<a href="注釈">` に化ける（誤変換）    |
| `![](x.png)`                 | **`<img>` ごと落ちる**（代替テキストが空） |
| `- [ ] やること`             | `<li class="unchecked">` になり、**`[ ]` の文字が消える** |

最後の 2 つは既に踏んでいて、前者は「書き出す文字列だけ `![ ](` に
差し替える」という回避で塞いでいた（`_fill_empty_alt`）。後者は塞げておらず、
**書き出した HTML と PDF ではチェック済みかどうかが分からなかった**。

## 決定

**書き出しの変換を markdown-it-py に移す。** `core/html.py` を新設し、
`editor/exporter.py` は「ページに組む」「画像を埋める」「PDF に流す」に徹する。

- パーサはエディタ（`core/block_parser.py`）と**同じ設定**にする。画面で
  表として解釈されたものが書き出しでは段落、という食い違いを作らない
- ただし `html` だけは切る。**commonmark プリセットは既定で `html: True`**
  （実測）で、本文の `<script>` がそのまま出力に通る
- PDF は生成した HTML を `QTextDocument.setHtml()` に渡す
- **HTML と PDF は同じ文字列を使う**。経路を分けると片方だけ直す事故が起きる
- チェックボックスは `☐` / `☑` の文字にする。クラス名だけではどこでも印が出ない

`core/` に置いたので PySide6 に依存せず（R3）、書き出しの中身を
ヘッドレスで検査できる。

## 根拠

**Qt のリッチテキストが何を解すかを先に実測した。** ここが駄目なら PDF が
成立せず、この案自体が没になる。

| | |
|---|---|
| 表の罫線・セルの余白（CSS） | 効く |
| `<pre>` の等幅・背景 | 効く |
| 打ち消し線・リンク・`<hr>` | 効く |
| `data:` URI の画像 | 効く（赤い画素を数えて確認） |
| `border-left`（引用の縦線） | **効かない** |
| `border-collapse` / `max-width` | 無視される（壊れはしない） |

引用の縦線は PDF では出ない。**これは移行前から出ていなかった**ので後退では
ない（ブラウザで開く HTML には出る）。

**代わりの案も見た。**

| 案 | 内容 | 問題 |
|---|---|---|
| A | `setMarkdown()` のまま、記法ごとに文字列を細工して回避 | `_fill_empty_alt` の後始末が記法の数だけ増える。フェンスの言語は**どう細工しても復元できない** |
| B | **markdown-it-py で描く** | 書き出しのテストを総取り替えする |
| C | 書き出し専用に別のパーサを足す | パーサが 2 つになり、画面と書き出しの解釈が割れる |

A が行き止まりであることが決め手。B の「総取り替え」は実際には起きず、
既存 34 件は**1 件も変えずに通った**。振る舞いで書かれていたため。

## 影響

- **R2 の例外が無くなった。** アプリのどこからも `setMarkdown()` を呼ばない。
  `tests/test_architecture.py` の除外リストを削除した
- B-3（Qiita 記法）・B-4（Mermaid）・B-5（数式）が乗る土台ができた。
  フェンスの言語が残るので、B-4 は `<pre><code class="language-mermaid">` を
  拾えばよい
- **チェックボックスが書き出しに出るようになった**（今まで消えていた）
- **PDF にも「保管フォルダの外は読まない」が効くようになった。** 以前は
  `setBaseUrl()` でその場で解決していたので、`../` を書けば外の画像も入った。
  HTML と同じ埋め込み経路に揃えた副産物
- 出力が `style="..."` だらけの Qt 製 HTML から、意味づけされた HTML に
  変わった。受け取った側が CSS で手を入れられる
- `_fill_empty_alt` を削除した。markdown-it は `<img>` を落とさない
