# ADR-0020: 数式ブロックをエディタ内で組版して表示する

日付: 2026-08-19
状態: 採用（TASKS これから I-1 の「依存の判断が先」を解決して実装）

## 文脈

`$$ 〜 $$` の数式ブロックは、これまでエディタ内では生の LaTeX +
コード背景で表示し、組版は書き出し（HTML / PDF、latex2mathml → MathML）
でだけ見えていた。インライン展開の壁は依存の重さと見ていた:
数式 = matplotlib（+60MB）、Mermaid = QtWebEngine（+200MB）。
30MB の pyobjc すら ctypes で回避してきた方針と衝突する。

## 判断（依存）

実測で前提が 2 つとも崩れた:

1. **数式に matplotlib は要らない。** ziamath（純 Python・ziafont 込みで
   約 3.3MB）が TeX 品質の SVG を 6ms/式（初回）/ 1ms（フォントが温まった
   あと）で出す。SVG → QPixmap は Qt 標準の QtSvg で足りる。
   依存方針の例外は**不要**だった
2. **QtWebEngine は最初から入っていた。** `pyside6` メタパッケージが
   Addons ごと同梱している（.venv 1.3GB の内訳）。Mermaid を受ける場合の
   +200MB は既に払い済みで、判断の対象は「JS アセット（mermaid.min.js
   ≈ 3MB）を同梱するか」に縮む（→ Mermaid は別途判断）

## 決定（表示）

- 描画は `editor/math_cache.py`。ziamath の SVG を QtSvg で QPixmap にし、
  （式・大きさ・色・幅）で 64 件までキャッシュ。Retina は 2 倍で描く。
  **QtSvg は SVG2 の `<symbol>/<use>` を描けない**（枠線だけ出て文字が
  消える。実測）ので `ziamath.config.svg2 = False` を必ず立てる
- 表示は画像（ADR-0004）と同じ手口: 式の行を 0.5pt に潰し、最初の本文行の
  先頭 1 文字を透明のまま拡大して絵の高さを予約。絵は paintEvent が描く。
  ソース不変（R1）・位置 1:1（R4）・Undo 消費 0
- リビールは**式全体**（表 ADR-0017 の行単位とは違う判断）。キャレットが
  式のどの行に入っても式全体が生の LaTeX に戻る。途中の行だけ生に戻ると
  式の断片と絵が同時に見えて読めない
- 壊れた式・閉じていない式・Raw モードは生のまま（直せる状態を保つ）。
  色とサイズはテーマ・文字サイズに追従する（キャッシュキーに含む）
