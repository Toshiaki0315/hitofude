# ADR-0027: 画像とスキャン PDF を文字にする（OCR）

日付: 2026-08-22
状態: 採用（`.app` に同梱物が 1 つ増える）

## 文脈

**文字が入った PDF は既に読める**（F-2。QtPdf が抽出、60 節で 31ms、依存ゼロ）。
足りないのは**スキャンした PDF と JPEG/PNG**で、そこには文字が入っていない。

手元の LLM（L-1〜L-3）が画像も読めるので、それで足りるか実測した。同じ
画像（会議メモ 9 行、日本語）を読ませた結果。

| 読み手                | 所要     | 結果                                               |
| --------------------- | -------- | -------------------------------------------------- |
| **macOS の Vision**   | **0.85 秒** | **全文正しい**（金額・日付も）                   |
| `gemma3:4b`（Ollama） | 17.3 秒  | 営業**部**→営業**時間**、**増額**→**慣願**、用意する→用意**意**する |

**言い換えではなく読み違い**で、会議メモとしては使えない（部署名と要望の
中身が別のものになった）。20 倍遅くて間違えるなら選べない。

ただし**大きなモデルを積める人もいる**（ユーザー指摘）。27b 級や
`qwen2.5vl` なら結果は変わりうる。**片方に決め打たない。**

## 決定

1. **読み手を 2 つ持ち、設定で選ぶ。** 既定は **macOS**（速くて正確、
   モデルの取得も要らない）。**手元の LLM** はモデルを選べる人向け
2. **macOS 側は小さな実行ファイルを同梱する**（Swift + Vision）。呼び方を
   2 つ比べた。

   | 方法                        | 増えるもの | 動いたか                     |
   | --------------------------- | ---------- | ---------------------------- |
   | **Swift の実行ファイル**    | **63KB**   | **動いた**（上の実測がこれ） |
   | `pyobjc-framework-Vision`   | 30MB       | この場では結果が返らなかった |

   30MB の pyobjc を断ってきた方針（`app.py`）とも噛み合う。**引き換えに
   署名・公証の対象が 1 つ増える**（残る唯一のタスクがそこなので、
   手順書に一緒に書く）
3. **LLM 側は既にある経路を使う。** Ollama の `/api/generate` に `images`
   を足すだけで、新しい依存は無い。**モデルは設定のものを使う**
   （画像を読めないモデルを選ぶと空が返る。そのときはそう知らせる）
4. **どちらも無ければ機能ごと畳む**（G-3 と同じ作法）。実行ファイルが
   無い（ビルドで作れなかった）・Ollama が動いていない、のどちらでも
   「読み取りできません」と出す
5. **PDF は文字が取れなければ OCR に回す。** 取れるなら今まで通り
   （速くて正確なほうを黙って捨てない）
6. **元のファイルは触らない**（F-2 と同じ）。読み取った文字で**新しい
   ノートを作る**だけ

## 作り方と配布

道具は `tools/ocr/ocr.swift` の 1 ファイルで、`make ocr-tool` が
`hitofude/resources/bin/hitofude-ocr` に作る（`make run` からも呼ばれる）。
**成果物は git に入れない**（`.gitignore`）。

**`swiftc` が無い環境では作られない。** アプリは今まで通り動き、
macOS 側の読み取りだけが「使えない」と答える。

配布では `codesign` の対象がこの実行ファイルにも要る（0-C-2 の手順に
書き足す）。

## やらないこと

- **画像をノートに貼るときの自動 OCR。** 貼るたびに待たされ、頼んでいない
  処理が走る（ADR-0025 の「自動で走らせない」と同じ）
- **傾き補正・段組の解析。** Vision が返す並びをそのまま使う。凝ると
  「元と違う順で読める」不具合を自分で作り込むことになる

## 結果

- スキャンした資料と写真をノートにできる。**既定では手元だけで完結**し、
  モデルの取得も要らない
- 大きなモデルを持っている人は、設定で LLM に替えられる
- `.app` に 63KB の実行ファイルが 1 つ増え、署名の対象も 1 つ増える
- `swiftc` が無い環境ではビルド時に作られず、**macOS 側の読み手だけが
  使えない**（アプリは今まで通り動く）
