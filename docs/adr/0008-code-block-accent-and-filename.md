# ADR-0008: コードブロックの左バーをやめ、ファイル名を出す

- **日付**: 2026-08-10
- **状態**: 採用
- **覆す対象**: spec.md §5.2 の表「コードブロック: 等幅 + ブロック背景 +
  **左 4px アクセントバー**」

## 背景

ユーザーからの指摘 2 点。

1. コードブロックの左に出るアクセントバー（強調色）が要らない
2. ` ```python:aaa.py ` のファイル名が、**書き出しには出るのに画面に出ない**

2 について。B-3 でファイル名を書き出しに出せるようにしたが、画面側は
フェンスの行ごと潰していたので、ファイル名はどこにも出ていなかった。
B-3 の合意は「画面も書き出しも」だったので、片手落ちだった。

## 決定

**アクセントバーを描かない。** 背景だけでコードブロックだと分かる。

**ファイル名を画面にも出す。** フェンスの行の高さを作り、そこへ描く。

- 高さは R4 と同じ「文字の大きさ」で作る。`QTextBlockFormat` は使わない（R5）。
  ADR-0004 が画像の行高で使ったのと同じ手
- **記号は透明にする。** 0.5pt に潰すと 1px 未満になって書いても見えず、
  素の大きさだとバッククォートが出てしまう
- ファイル名の無いフェンス（` ```python `）は今まで通り潰す
- 言語とファイル名は `BlockInfo.lang` / `BlockInfo.code_name` に分けて持つ。
  `lang` に `python:aaa.py` を入れると、色分けの仕組みが言語を見つけられない
  （`core/html.py` の描画規則と同じ理由）

## 根拠

**アクセントバーについて。** 仕様書がこれを書いた時点では、縦線を使う要素は
引用しか無かった。その後 `:::note` の囲み（B-3）が左の縦線を使うようになり、
**同じ形の線が 3 種類**（引用・囲み・コード）並ぶことになった。

| 要素 | 表し方 |
|---|---|
| 引用 | 左に縦線（灰） |
| `:::note` | 左に縦線（青 / 黄 / 赤 / 灰） |
| コードブロック | 背景（面） |

コードブロックは**背景という別の表し方を既に持っている**ので、線を外しても
見分けが付かなくなることはない。線を残すほうが、意味の違う 3 つが同じ形に
なって紛らわしい。

**ファイル名について。** 画面と書き出しで見え方を割らない、というのは B-2 で
決めた原則（ADR-0007）。書き出しにだけ出る状態は、その原則に反していた。

## 影響

- `DecorationKind.CODE_ACCENT` を削除。`theme.accent` はコードブロックには
  使わなくなった
- `BlockInfo` に `code_name` が増えた。`lang` は言語だけを持つようになった
  （`` ```python:aaa.py `` の `lang` は `"python"`）
- ファイル名のあるフェンスは**行の高さが変わる**（潰れなくなる）。カーソルを
  入れたときの高さの跳ねは、元から潰れていない行なので起きない
- spec.md §5.2 の表と食い違う。仕様書側にこの ADR への参照を書いた
