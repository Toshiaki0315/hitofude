# ADR-0032: Hitofude を「覚書（OboeGaki）」へ改名する

- 状態: 採用
- 日付: 2026-08-27
- 関連: ADR-0023（履歴は作り直せない）

## 何を決めたか

「Hitofude（一筆書き）はエディタっぽくない」というユーザーの感想から、
候補を出して**覚書（OboeGaki）**に決めた。使い分けは:

| 用途 | 名前 |
|---|---|
| 表示名（メニューバー・About・通知） | **覚書** |
| アプリのファイル名（.app / アイコン） | **OboeGaki** |
| 保管フォルダの既定名 | **OboeGakiNotes** |
| メタデータフォルダ | **.OboeGaki** |
| バンドル ID / QSettings の保存先 | **app.oboegaki.editor** |
| Python パッケージ名 | **hitofude のまま**（ユーザーに見えない。66 ファイルの import を動かす理由が無い） |

## 引っ越し（初回だけ・一方向・改名 1 回）

1. **設定**: 新ドメインが空で旧ドメインにあれば全鍵を写す。
   **fallback は切る**——macOS の QSettings は OS のグローバル既定
   （AppleLanguages など）を混ぜて見せるため、切らないと「空」の判定が
   壊れ、Apple の鍵まで写す（実機で確認）。旧側は消さない
2. **メタデータ**: 保管フォルダを開くとき `.hitofude` → `.OboeGaki` へ
   rename。履歴（ADR-0023）は作り直せないので中身ごと連れて行く。
   両方あれば新しい側が正
3. **既定の保管フォルダ**: パスを保存していない既定値運用の人は、
   旧の `~/Documents/HitofudeNotes` が在ればそれを**使い続ける**。
   フォルダは動かさない（iCloud / Dropbox の同期下にあり得る）。
   新しい既定名は新規ユーザーだけに効く
4. **退避（クラッシュ復元）**: `Application Support/Hitofude` → `OboeGaki` へ rename

実機（この開発機は既定値運用だった）で 1 と 3 の穴を実際に踏んで確認した。

## 変えないもの

- Python パッケージ `hitofude/`、pyproject の name、`make run`（`python -m hitofude`）
- 保管フォルダの実体（既存ユーザーのフォルダ名はそのまま）
- ~~アイコンの絵柄~~ → 同日、名前に合わせて描き替えた（角を折ったメモ用紙 + 墨の題 + 朱点。筆致の弧だった旧デザインから墨と朱を引き継ぐ）

## 既知の縁

- **旧アプリと新アプリの同時起動**は守れない。引っ越しの rename が
  旧アプリの保持するロックの下からフォルダを動かすため、二重起動
  ロックが別々の場所を指す。改名をまたいで新旧を並行起動しない前提
- 起動の実順序は「ロック → ensure_layout」。ロック側
  （app.acquire_vault_lock）が先に管理フォルダを作るため、
  **引っ越しはロック側でも通す**（通し検証で発覚して直した）
