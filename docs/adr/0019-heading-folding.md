# ADR-0019: 見出し単位の折りたたみ

日付: 2026-08-19
状態: 採用（TASKS の見送り判断「QPlainTextEdit に仕組みが無い」を反証して転換）

## 文脈

見出し単位で節を畳みたい（TASKS これから I-4）。当初は「`QPlainTextEdit`
に折りたたみの仕組みが無い」として見送っていたが、スパイクで反証した:

- `QTextBlock.setVisible(False)` + `markContentsDirty()` で行が畳まれ、
  後続行の y 座標が詰まる（実測: 174px → 54px）
- `toPlainText()` は不変（R1 無傷）
- Undo スタックの消費 0（R5 の轍を踏まない）
- 畳んだまま編集してもレイアウトは破綻しない

## 決定

1. **畳む範囲は純関数**（`core/folding.section_end`）。見出しの次の行から、
   同じか浅い見出しの手前まで。H1 は配下の H2 ごと巻き込む
2. **開閉 UI は左余白の三角**。ADR-0016 で生まれた documentMargin 12px に
   開閉三角（開 = 下向き / 閉 = 右向き）を `paintEvent` で描き、
   その帯のクリックで開閉する。本文の開始位置は変えない
3. **状態はセッション限り**。ノートを開き直せば全部開いた状態に戻る。
   `.hitofude` への永続化（R9 の範囲）は要望が出てから
4. **隠れた行へは入れない**を不変条件にする:
   - キャレットが隠れた行に入ったら自動で開く（検索・見出しジャンプ・
     Undo もキャレット移動なので、個別の連携なしで全部ここを通る）
   - 畳むとき、範囲内にいたキャレットは見出しの行末へ退避する
   - 編集で見出しでなくなったら（`#` を消したら）開く。入る口が消えるため
   - Raw（ソースモード）に入ると全部開く。ソースを全部見せるモードで
     隠れた行があっては嘘になる
5. 畳んだ節の中の飾り（表の罫線・縦バー等）は描かない。高さ 0 の矩形でも
   罫線は 1px のゴミとして残る（回帰テストあり）

## 影響

- 開閉のたびに再ハイライトは走らない（R7 無傷）。可視状態はハイライトと
  独立した `QTextBlock` の属性で、`markContentsDirty` はレイアウトだけを
  更新する
- 入れ子で畳んでいた節は、外側を開くとまとめて開く（内側の畳み状態は
  保持しない）。単純さを優先した割り切り
