# ADR-0028: 表のセル内の改行は `<br>`

日付: 2026-08-25
状態: 採用

## 文脈

表のセルを複数行にしたい（ユーザー要望）。ケースは 2 つ:

1. セルの中身が幅を超えたら折り返す — **ADR-0017 で実装済み**
2. セルの中で明示的に改行を指示したい — 本 ADR

GFM の表はセル内改行の公式記法を持たない。表の行はソース上 1 行で
なければならない（`|` で区切る構文の前提）ので、行末バックスラッシュ等の
「行を分ける」系記法は構造的に使えない。

## 決定

**`<br>` を採用する**（`<br/>` `<br />`、大文字小文字混在も同義）。
GitHub / Qiita とも `<br>` が事実上の標準で、他所からコピーした表が
そのまま生き、書き出した `.md` も他のツールで通じる（R1 の精神）。

**表のセルの中だけ**で意味を持つ。本文中の `<br>` は文字のまま
（書き出しでもエスケープされる。生 HTML を通さない判断は変えない）。

### 画面

- `<br>` 入りの表は、幅に収まっていても**折り返し描画**（ADR-0017 の
  予約機構）に入る。行の高さを変えるにはこの機構が要る。収まる表なら
  列幅は自然幅のままなので、見た目は行が高くなるだけ
- 列の自然幅は**断片の最長**で数える（`<br>` を入れると列が痩せる、
  という直感どおりの効き）
- キャレットを入れた行は生の Markdown に戻って編集できる（従来どおり）

### 整形（ユーザー決定 2026-08-25）

ソースの縦線は **`<br>` 込みの全長**で揃える。整形はソースの見た目を
揃える機能で、断片幅で数えるとソース上の縦線がずれる。表示側の列幅は
描画時に `wrapped_columns()` が計算するので、両者は矛盾しない。

### 書き出し

- HTML / PDF / HTML コピー: 表セル内の `<br>` を hardbreak トークンに
  分解して出す（`html: False` は維持＝`<script>` を通さない判断のまま。
  インラインコードの中は `code_inline` トークンなので対象外）
- PowerPoint: セル文字列の `<br>` を改行文字に

## 変えないもの

- 検索・カーソル位置: ソースに `<br>` が実在するので 1:1 のまま（R4）
- 文字数: `<br>` は今までどおり数える
- 整列記法（`:---:`）: 折り返し描画では左揃え、書き出しでは効く
  （ADR-0017 の既存決定を踏襲）
