# ADR-0015: 空本文のタイトルはファイル名ではなく「無題」にする

- **日付**: 2026-08-18
- **状態**: 採用
- **覆す対象**: spec.md §7.2「タイトル: 最初の H1 → 無ければ最初の非空行 →
  無ければ**ファイル名**」の最後のフォールバック

## 背景

タイトルは本文から導かれ、ファイル名はタイトルへ追従する（ADR-0005）。
このためユーザーが一度本文を書くと、ファイル名はそのタイトルになる
（`# 会議メモ` → `会議メモ.md`）。

その後**本文を全部消す**と、タイトルの導出が spec §7.2 のフォールバックで
ファイル名（= 直前のタイトル）に落ち、ウィンドウにも一覧にも
「会議メモ」が残り続ける。本文が空なのにタイトルが残って見えるのは
表示が嘘をついている、という指摘があった（ユーザー要望 2026-08-18）。

ファイル名はタイトルの**写し**なので、写しをタイトルの出どころに使うと
循環ができて、消したはずのものが戻ってくる。

## 決定

タイトルのフォールバックを「無題」（`core/document.UNTITLED`）にする。

- 決定順: 最初の H1 → 無ければ最初の非空行 → 無ければ**「無題」**
- ファイル名は既存の追従機構（`_rename_if_title_changed`）がそのまま
  効くので、本文を消して保存すると `無題.md`（衝突時は連番）へ戻る

## 根拠

- 本文が唯一の真実（R1 / ADR-0005）。タイトルも本文だけから導けば、
  「本文を消す」と「タイトルが消える」が一致する
- 新規ノート（`無題.md`・空本文）の表示は変わらない
- 失うもの: 外部で作られた「中身が空だが名前に意味があるファイル」の
  題名がファイル名から拾えなくなる。空ノートは開けば直せるし、
  本文を 1 行書けば済むので、循環の解消を優先した

## 影響

- `core/document.py`: `Note.title` のフォールバック変更。`UNTITLED` は
  ここが持ち、`storage/vault.py` は import で再輸出
- spec §7.2 に「→ ADR-0015 で変更」を追記
- 回帰テスト: `tests/core/test_document.py`（空本文・front matter のみ）、
  `tests/ui/test_main_window_flow.py::TestClearedNote`（消す → 無題へ戻る、
  ファイル名も追従）。`tests/storage/test_index_db.py` の
  「空ノートの外部改名で題名がファイル名に追従する」は旧仕様の固定
  だったので、新しい判断へ書き換えた
