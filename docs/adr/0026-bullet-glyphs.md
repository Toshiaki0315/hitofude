# ADR-0026: 箇条書きの記号を点で描く

日付: 2026-08-22
状態: 採用（spec §5.2 の表が「v1 では素のまま」としていた選択肢を採る）

## 文脈

`- ` と `* ` が**書いた通りの記号のまま**出ていた（ユーザー報告の画像）。
`-` で書いた人と `*` で書いた人で見た目が変わり、**同じ深さなのに違うものに
見える**。入れ子も、字下げの幅でしか読み取れない。

仕様書 §5.2 の表はこの行をこう書いている。

> **リストマーカー** `- `, `1. ` … **隠さない**（記号自体が意味を持つ表示要素）
> — （`- ` は `•` に置換描画してもよいが v1 では素のまま）

**但し書きのほうを採る。** 置換描画は最初から許されていた。

## 決定

1. **箇条書きの記号（`-` / `*` / `+`）を潰して、点を描く。** 文字は消さない
   （R1 / R4）。潰すのは `setFontPointSize(0.5)` で、キャレット位置と
   ソースのオフセットは 1:1 のまま。**行にカーソルを入れると記号が戻る**
   （マーカー隠しの約束。§3.3）
2. **深さで形を替える**（`disc` ● → `circle` ○ → `square` ■）。HTML の
   `list-style-type` と同じ並び。**4 段目より深いところは四角のまま**
   （記号を増やしても見分けが付かない）
3. **番号付き（`1. `）は触らない。** 数字は情報で、点にすると何番目か
   分からなくなる
4. **`- [ ]` は箱のまま**（E-1）。点と箱が二重に出ない
5. 描くのは `painter_overlay`（R5。ブロックの見た目はここが唯一の担い手）。
   位置と幅の作り方は**チェックの箱と同じ手**（`_hide_checkbox_slot` と
   同じく字送りで幅を確保する）

## 深さの数え方（既知の限界）

深さは `block_parser._indent_level`（**字下げ 2 文字で 1 段**）を使う。
アプリの Tab が入れるのも 2 文字（`input_handler.INDENT`）なので、
**このアプリで書いたノートは素直に ● ○ ■ になる。**

**行だけを見て正確な深さは決まらない**（CommonMark では親のマーカー幅で
決まる）。4 文字下げて書いた行は 2 段ぶん深いと見なされ、● のすぐ下が
■ になる。正確に出すには文書全体の解析結果が要り、**打鍵のたびに
全体を読み直すことになる**（R7 と衝突する）ので採らない。

## 結果

- `-` で書いても `*` で書いても同じ見た目になる
- 入れ子が形で読める（字下げの幅を目で測らなくてよい）
- ソースは 1 文字も変わらない。他のアプリで開けば `- ` のまま
- 書き出し（HTML / PDF）は markdown-it-py が担うので、**元から点が出ていた**。
  画面がそちらに追いついた形になる
