# ADR-0001: インラインスキャンの順序でリンクを裸の URL より先に確定する

- **日付**: 2026-08-08
- **状態**: 採用
- **覆す対象**: spec.md §6.5「処理順」の 2 と 3

## 背景

spec §6.5 は確定順を次のように定めている。

```
1. インラインコード
2. 自動リンク <https://...> と裸の URL
3. 画像 ![alt](url) → その後 リンク [text](url)
4. 強調 …
```

同じ節が「先に確定したものが優先」「確定済み範囲のマスクを持ちながら段階的にスキャンする」
とも定めているため、この順序をそのまま実装すると次が起きる。

入力 `[Qt のドキュメント](https://doc.qt.io/)` に対して、

1. 規則 2 が `https://doc.qt.io/` を裸の URL として確定し、その範囲をマスクする
2. 規則 3 の `\[...\]\(...\)` は URL 部分がマスク済みのため棄却される

結果として**リンク記法が一切成立せず**、`[` `]` `(` `)` が生の文字として残り、
`Cmd+クリック` でブラウザを開く動作（§5.2）も効かない。

## 決定

確定順を次に変更する。

```
1. インラインコード
2. 画像 ![alt](url) → リンク [text](url)     ← 3 から繰り上げ
3. 自動リンク <https://...> → 裸の URL       ← 2 から繰り下げ
4. 強調 → 5. 取り消し線 → 6. ハイライト → 7. タグ
```

## 根拠

- リンクを先に確定しても自動リンクは壊れない。`<https://x.com>` は
  `\[...\]\(...\)` にも裸の URL パターンにも一致しないため、影響を受けない。
- 逆に裸の URL を先に確定すると、上記のとおりリンクが必ず壊れる。
  非対称なので、順序は一意に定まる。
- 裸の URL を「`](` の直後では一致させない」といった否定先読みで回避する案も
  検討したが、記法の一部を別の記法のパターンに埋め込むことになり、
  マスク方式の利点（各規則が独立している）を失う。

## 影響

- `hitofude/core/inline_scanner.py` の `_SCAN_PASSES` の並び。
- spec §6.5 の番号付きリストは、この ADR で置き換えられたものとして読む。
- 不可侵ルール（CLAUDE.md §3）への影響はない。R8（インラインは自作スキャナ、
  ブロックは markdown-it-py）の分担は変わらない。
- 回帰テスト `tests/core/test_inline_scanner.py::TestLink::
  test_リンク内のURLを裸のURLとして重複検出しない` がこの決定を固定している。
