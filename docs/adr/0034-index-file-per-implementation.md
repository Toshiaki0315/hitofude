# ADR-0034: 索引のファイル名を実装ごとに分ける

- 日付: 2026-09-05
- 状態: 受理
- 関連: R9（索引は捨ててよいキャッシュ）、ADR-0032（改名）、spec §7.1 / §7.3

## 背景

利用者が `make run` で起動できなくなった。

```
sqlite3.OperationalError: no such column: modified_at
```

`.OboeGaki/index.sqlite` に**このアプリが知らない形**が入っていた。

| | この実装（Python / PySide6） | 実際に置かれていた形 |
| --- | --- | --- |
| `user_version` | 5 | **6** |
| `notes` の主キー | `id` | **`path`** |
| 列 | `modified_at` `created_at` `trashed` `search_key` … | **無い**。代わりに `title_key` |

`title_key` も `SCHEMA_VERSION = 6` も、このリポジトリのどの ref にも
存在しない。書いていたのは**作り直し版**（`src-tauri/src/index_db.rs`。
Tauri / Rust）で、`MANAGED_DIR = ".OboeGaki"` と
`INDEX_FILE = "index.sqlite"` により**同じ保管フォルダの同じファイル**を
使っていた。

落ちること自体は別の不具合として直した（形を見る前に `SCHEMA` を流して
いた）。だが直しても、**同じ名前を奪い合う状態は残る**。どちらも
「知らない形なら作り直す」ので、**交互に起動するたび全ノートを読み直す**。
今は 18 ノートで一瞬だが、増えれば起動の待ち時間になる。

## 決定

**索引のファイル名を実装ごとに分ける。** この実装は
`index-hitofude.sqlite` を使い、素の `index.sqlite` には触らない。

名前は `storage/index_db.INDEX_FILE` を**唯一の出所**とする。
呼ぶ側（`ui/main_window`、`scripts/`、テスト）は書き写さない。

`hitofude` は Python 側のパッケージ名で、ユーザーには見えない（ADR-0032）。
**衝突しないことだけが要件**なので、実装を名指しする形にした。

## 検討した他の案

| 案 | 退けた理由 |
| --- | --- |
| 保管フォルダを分ける | `history/`（作り直せない。ADR-0023）まで分かれる。ノートも二重管理になる |
| 形を見分けて共用する | 索引の形は双方が独立に変える。**片方が変えるたびもう片方が壊れる**——「同じことをする道を 2 つ作らない」に真っ向から反する |
| 何もしない | 移行が終わるまで起動のたび全件読み直し。ノートが増えるほど効く |

## 影響

- 既にある `.OboeGaki/index.sqlite` は**こちらからは消さない**。今はもう
  別のアプリのものかもしれない
- こちらの索引は次回起動時に `index-hitofude.sqlite` として作り直される。
  索引は捨ててよいキャッシュ（R9）なので、失うものは無い
- R9 の書き方（`.OboeGaki/index.sqlite` を名指し）を
  「`.OboeGaki` の索引ファイル」に改める。**捨ててよいのは索引だけ**という
  中身は変わらない
