# ADR-0031: 表のセルの中のインライン記法を描き分ける

- 状態: 採用
- 日付: 2026-08-26
- 関連: [ADR-0029](0029-table-body-font.md)（表は描画側が組む）、CLAUDE.md R8

## 何が起きたか

使い方のノートのショートカット表で、`` `Cmd+N` `` のバッククォートが
そのまま見えているとユーザーから報告があった（2026-08-26）。

ADR-0029 の副作用。それまで収まる表はソースの文字がそのまま本文として
表示され、インライン走査が記号を隠して体裁を当てていた。表を常に
描画側が組むようにしたことで、セルの文字は `WrappedRow` の**生の
文字列**をそのまま `drawText` する経路になり、走査を通らなくなった。

## 決めたこと

セルの文字列を core で**記号を落とした断片の並び**（`Fragment`）にする。

- 走査は本文と同じ自作スキャナ（R8。`inline_scanner.scan`）。core → core
  の依存なので R3 も無傷
- 対象は `**強調**` `*斜体*` `` `コード` `` `~~打ち消し~~`
  `::ハイライト::` `#タグ`。入れ子は種類の集合（`kinds`）で持つ
- **リンク・画像・数式は対象外。** 記号だけ消すと URL が見えなくなるうえ、
  描いた文字は押せない（当たり判定が無い）。生のまま見せて、キャレットを
  入れて扱ってもらう。リンクを札として描いて活性化させるかは別の判断
- 折り返しと列の自然幅は**見える文字**で数える。コードの断片は等幅で
  描かれるので、幅も等幅（`code_measure`）で測る
- 描画は断片ごとに書体と色を替える。**測るフォントと描くフォントを
  1 か所（`cell_font`）で共有する**。別々に組むと、測った幅と描いた幅が
  ずれて右端が欠ける（ヘッダの太字で踏んだ轍と同じ）
- 寄せ（`---:` など）は drawText のフラグではなく、断片の開始位置に
  折り込む（断片が複数あると 1 つの矩形では寄せられない）

## 引き換え

- セルの中のコードが等幅になったぶん、列幅の計算にフォントが 2 つ
  絡む。整合は `cell_font` の共有と回帰テストで守る
- キャレットを入れた行は従来どおり生の Markdown（記号込み）に戻る。
  「見た目と編集で幅が変わる」のは ADR-0029 で織り込み済み

## 追記（同日）: 隠した行の帯のゴミ

記号は消えたが、操作列の左端に灰色の粒が残っていた（ユーザー報告・続報）。
正体は**隠したソース行に描かれ続けていたインラインの帯**（コードの下地
など。`BlockData.spans` から painter が引く）。行は 0.5pt に潰れて
見えないのに帯だけが残り、潰れた位置（左端から数 px）に 2〜3px の粒と
して出ていた。

描画側が組んでいる行（`wrapped` あり）には帯を出さないようにした。
セルの中身は断片が自前の下地を持つので帯は要らない。キャレットの行は
`wrapped` が無く、生の Markdown に本文と同じ帯が付く（一貫性）。
