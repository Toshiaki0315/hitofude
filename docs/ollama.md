# Ollama の入れ方と、モデルの選び方

Hitofude から**ローカルLLM**を使う機能（要約・レビュー・関連ノート探し）の
下ごしらえ。アプリ側は `Cmd+6` の「アシスタント」で使える
（[ADR-0025](adr/0025-local-llm.md)）。ここは**その相手を用意する**手順書。

**なぜ Ollama なのか**は 3 行でいうと、(1) `.app` にネイティブ拡張を足さずに
済む（署名・公証を難しくしない）、(2) 別プロセスなので**モデルが落ちても
エディタは死なない**、(3) 4〜5GB のモデルは同梱できないので、入手と更新を
任せられる相手が要る。詳しくは ADR に書く。

**ノートは外に出ない。** Ollama は手元で動き、通信先は `127.0.0.1` だけ。
ネットが切れていても動く。

---

## 1. 入れる

**方法は 2 つ。どちらか 1 つでよい。**

### 公式のアプリ（おすすめ）

1. <https://ollama.com/download> から macOS 版をダウンロード
2. `Ollama.app` を「アプリケーション」へドラッグ
3. 一度起動する。メニューバーに常駐し、**以後は自動で立ち上がる**

### Homebrew

```bash
brew install ollama
```

こちらは**自分で起動する**（常駐しない）。使うたびに次を実行するか、
`brew services start ollama` で常駐させる。

```bash
ollama serve
```

### 入ったか確かめる

```bash
ollama --version
```

**動いているか**は次で分かる。`Ollama is running` と返れば準備完了。

```bash
curl http://127.0.0.1:11434
```

---

## 2. モデルを取る

```bash
ollama pull gemma3:4b
```

| したいこと           | コマンド                  |
| -------------------- | ------------------------- |
| 入っているものを見る | `ollama list`             |
| 今動いているものを見る | `ollama ps`             |
| 試しに話す           | `ollama run gemma3:4b`    |
| 消す                 | `ollama rm gemma3:4b`     |

モデルの実体は `~/.ollama/models` に置かれる。**ここは容量を食う**ので、
使わなくなったものは `ollama rm` で消す。ディスクの残りは
`du -sh ~/.ollama` で確かめられる。

---

## 3. どのモデルを選ぶか

### 目安の計算

**4bit 量子化で、10 億パラメータあたり約 0.6〜0.7GB。** これに文脈のぶんが
乗る（8k トークンでおよそ 0.5〜1GB）。Apple Silicon はメモリを CPU と GPU で
分け合うので、**モデルが本体メモリの 6 割を超えると急に遅くなる**（残りで
macOS とアプリが動けなくなり、スワップが始まる）。

### メモリ別

| 本体メモリ | 常用にすすめる      | 重い作業に         | 備考                                       |
| ---------- | ------------------- | ------------------ | ------------------------------------------ |
| 8GB        | `gemma3:4b`（3.3GB）| —                 | ここが下限。文脈は 4k までに抑える         |
| 16GB       | `gemma3:4b`         | `qwen3:8b`（5GB）  | 8b 級までなら余裕がある                    |
| 24GB       | `gemma3:12b`（8GB） | `qwen3:14b`（9GB） | 12b 級が常用にできる                       |
| **32GB**   | **`gemma3:12b`**    | `gemma3:27b`（17GB）| 27b も載るが、体感はっきり遅くなる        |
| 64GB 以上  | `gemma3:27b`        | `qwen3:32b`（20GB）| 70b 級（40GB）も動くが実用の速さではない  |

**日本語は `gemma3` 系と `qwen3` 系が扱いやすい**（下の実測は gemma3）。
モデルの顔ぶれはよく変わるので、最新は <https://ollama.com/library> を見る。

**1b 級は要約に使えない。** 速いが、日本語が壊れる（次節に実物）。

### 将来（関連ノート探しに使う埋め込み）

vault 全体から探す機能を作るときに要る。**今は入れなくてよい。**

```bash
ollama pull bge-m3          # 多言語。日本語も扱える（1.2GB 前後）
```

## 4. 実測（2026-08-22）

**MacBook Air M4 / メモリ 32GB / Ollama 0.32.14。**
使い方のノートの冒頭 4,000 字（約 2,000 トークン）を読ませて要約させた。

| モデル       | 読む速さ    | 書く速さ  | 要約 1 本 | 日本語         |
| ------------ | ----------- | --------- | --------- | -------------- |
| `gemma3:4b`  | 405 tok/s   | 33.8 tok/s| 12.8 秒   | 実用になる     |
| `gemma3:1b`  | 1,397 tok/s | 95.4 tok/s| 14.6 秒   | **壊れる**     |

- どちらも **GPU で 100% 動いた**（`ollama ps` で確認）
- **初回だけ 3.6 秒**、モデルの読み込みで余分にかかる。2 回目からは無し
- 1b は速いのに合計時間が伸びた。**要らない話を長く書く**ため
- 1b の実際の出力: 「このノートは、Markdown形式のノートを読みやすにつらい
  思いを抱いています」— **日本語として壊れている**。4b は素直に要約した

**読むのは速く、書くのは遅い。** ノート 1 本を丸ごと読ませる用途
（要約・レビュー）は現実的で、待ち時間のほとんどは**答えを書く時間**になる。

## 5. 設定

**基本はそのままでよい。** 触るとしたらこの 3 つ。

| 環境変数                  | 既定                | いつ変えるか                             |
| ------------------------- | ------------------- | ---------------------------------------- |
| `OLLAMA_HOST`             | `127.0.0.1:11434`   | **変えない**（下の注意）                 |
| `OLLAMA_KEEP_ALIVE`       | `5m`                | 読み込み待ちが煩わしいなら `30m` などに  |
| `OLLAMA_MAX_LOADED_MODELS`| 環境による          | 複数モデルでメモリが苦しいとき `1` に    |

公式アプリで常駐させている場合は、次のように設定して再起動する。

```bash
launchctl setenv OLLAMA_KEEP_ALIVE 30m
```

### 文脈の長さ（`num_ctx`）に注意

既定は控えめ（多くのモデルで 4k）で、**超えた入力は黙って切り捨てられる**。
長いノートを読ませるときは呼び出し側で広げる必要があるが、
**広げたぶんだけメモリを食う**。Hitofude は 8k を既定にしている
（4,000 字のノートが 2,000 トークンなので、日本語で 1 万字強に相当）。
設定（`Cmd+,`）の「LLM に渡す量」で変えられる。

### Hitofude 側の設定

アプリの設定（`Cmd+,`）で **モデル・ポート・渡す量**を選べる。
**送り先の機械は変えられない**（`127.0.0.1` 固定）。ポートを変えた
場合は、こちらも同じ番号に合わせる。

### 別のマシンの Ollama を使う（SSH トンネル）

**手元の Mac に大きなモデルが載らないが、デスクトップには載る**という場合、
そのデスクトップの Ollama を使える。**アプリの設定を広げる必要はない。**

仕組みはこう。SSH が「手元の 11500 番」を「向こうの 11434 番」に繋ぐので、
Hitofude から見た送り先は**今まで通り `127.0.0.1`** のままになる。

```
Hitofude ──▶ 127.0.0.1:11500 ══[SSH の暗号化]══▶ デスクトップ:11434（Ollama）
```

**この形の利点**は 3 つ。**通信が暗号化される**（Ollama 自体は平文 HTTP）、
**認証が SSH の鍵で行われる**（Ollama に認証は無い）、そして
**受け側を外に開かなくてよい**（`OLLAMA_HOST` は既定の `127.0.0.1` のまま）。

#### 1. 受け側（デスクトップ）

- Ollama を動かしておく（**`OLLAMA_HOST` は変えない**）
- リモートログインを入れる:
  「システム設定」→「一般」→「共有」→「リモートログイン」
- スリープすると使えなくなる。「システム設定」→「ロック画面」→
  「使用していないときはディスプレイをオフに」の下で、スリープを長めにする

#### 2. 手元の Mac

トンネルを張る（**繋いだままにする**。`-N` は「何も実行しない」）。

```bash
ssh -N -L 11500:127.0.0.1:11434 ユーザー名@デスクトップ.local
```

別の窓で、届いているか確かめる。`Ollama is running` と返れば通っている。

```bash
curl http://127.0.0.1:11500
```

#### 3. Hitofude 側

設定（`Cmd+,`）→「アシスタント」→「ポート」を **11500** にする。
送り先は `127.0.0.1` のままなので、**それ以外は何も変えない**。

#### 毎回打たなくていいようにする

`~/.ssh/config` に書いておくと `ssh 母艦` で済む。

```
Host 母艦
    HostName デスクトップ.local
    User ユーザー名
    LocalForward 11500 127.0.0.1:11434
    ServerAliveInterval 30
    ExitOnForwardFailure yes
```

`ServerAliveInterval` は切れたことに早く気づくため。**切れても自動では
繋ぎ直さない**ので、繋ぎっぱなしにしたい場合は `autossh` を使う。

```bash
brew install autossh
autossh -M 0 -N 母艦
```

#### うまくいかないとき

| 症状                                   | 見るところ                                          |
| -------------------------------------- | --------------------------------------------------- |
| `curl` が繋がらない                    | トンネルの窓が閉じていないか。`ssh` を張り直す      |
| `Connection refused` が向こう側で出る  | デスクトップで Ollama が動いていない                |
| 急に応答しなくなった                   | デスクトップがスリープした                          |
| 家の外（カフェなど）で使えない         | LAN の中だけ。VPN を張るか、ポートを 11434 に戻す   |
| ポートが使われている                   | `lsof -i :11500` で確かめ、別の番号にする           |

**持ち出すときはポートを 11434 に戻す**（手元のモデルに戻る）。切り替えは
設定のポートだけなので、覚えることは少ない。

### 外に開かない

`OLLAMA_HOST` を `0.0.0.0` にすると**同じネットワークの誰でも**手元の
モデルを叩ける。Ollama に認証は無い。**ローカルLLM を使う意味が消える**ので、
そうしないこと。Hitofude は `127.0.0.1` にしか繋がない。

## 6. うまくいかないとき

| 症状                             | 見るところ                                                       |
| -------------------------------- | ---------------------------------------------------------------- |
| `curl` が繋がらない              | 起動していない。`ollama serve` するか、アプリを立ち上げる        |
| ポートが使われている             | 他のものが 11434 を使っている。`lsof -i :11434` で確かめる       |
| 急に重くなる・ファンが回る       | モデルが大きすぎる。`ollama ps` で `100% GPU` か見る（`CPU` と 出ていたらメモリ不足でこぼれている） |
| 最初の 1 回だけ遅い              | 正常。モデルの読み込み（実測 3.6 秒）                            |
| 答えが途中で切れる               | `num_ctx` を超えている。入力を短くするか文脈を広げる             |
| 日本語がおかしい                 | モデルが小さすぎる。4b 以上にする                                |

---

## 7. やめるとき

```bash
ollama rm <モデル名>     # モデルを消す（容量が戻る）
rm -rf ~/.ollama         # 設定ごと消す
```

アプリ本体は「アプリケーション」から `Ollama.app` を捨てる
（Homebrew なら `brew uninstall ollama`）。

**Hitofude 側は Ollama が無くても動く。** ローカルLLM を使う機能が
使えなくなるだけで、ノートにも保存にも影響しない。
