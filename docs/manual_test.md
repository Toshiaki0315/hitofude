# 手動テストチェックリスト

自動化できない、または自動化しても意味が薄い項目（spec §10）。
リリース前と、Phase をまたぐ変更のあとに通す。

自動テストで担保済みの項目はここに書かない。**ここにあるのは
「機械では確かめられない」ものだけ**。

凡例: `[ ]` 未実施 / `[x]` OK / `[!]` NG / `[-]` 今回は対象外 /
`[a]` **自動テストで担保**（人が見なくてよい。根拠のテストを期待欄に書く）

`[a]` は目視していない。**機械が確かめられることは機械に任せ、人は
`[ ]` だけを見る**ための印。増えすぎた項目を人が全部たどるのは現実的でなく、
たどれないチェックリストは形だけのものになる。

**NG が 1 つでもあれば、末尾の「記録」に何が起きたかを書く。**
チェック欄は目印にすぎず、後から読んで分かるのは記録のほうだけ。
NG は直す前に回帰テストを書く（CLAUDE.md §1）。

## 1. 日本語入力（IME）

自動テストで再現できない**（CLAUDE.md §1 に記載）。

## 4. データを失わないこと

このアプリで最も避けたい事故。

**復元ダイアログは「めったに出ないのが正常」。** 実測した時間の流れ:

| 打鍵からの経過 | 状態                                                           |
| -------------- | -------------------------------------------------------------- |
| 〜200ms        | まだ何も無い                                                   |
| 200〜800ms     | `.hitofude` に退避がある（**ここで落ちると復元を尋ねられる**） |
| 800ms〜        | 本体ファイルに保存済み。退避は消える（**尋ねる必要が無い**）   |

手で `kill -9` を撃つ頃には保存が済んでいる。**復元が出ないのは正常**で、
出るのは打鍵直後に落ちたときと、保存が詰まっている（競合が未解決など）ときの保険。
